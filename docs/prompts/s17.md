## 5件の内容と、それぞれの罠

### U2: 「すべて開く」の永続範囲
現状は分析IDごとに localStorage へ開閉を保存し、**銘柄をまたいで維持される**
（memory: collapsible-analysis-pattern）。「すべて開く」を押した状態が
次の銘柄にも引き継がれてよいのかを決めること。**決めた理由をコードに残すこと。**

### FU20: sitemap が価格取得可否を検証しない
app/sitemap.ts は TICKER_PAGE_INSTRUMENTS を無条件に並べる。取得に失敗する銘柄は
ページ側が noindex を返すので、**sitemap に載せた URL を自分で noindex している**状態。
9613 は PRICE_UNAVAILABLE_TICKERS で手動除外しているが、**手動台帳は腐る**。

**罠: sitemap の生成時に98銘柄ぶん Yahoo を叩かせないこと。** ビルド/リクエストで
98本の外部取得を走らせる設計にすると FU15（投信10年が8秒）と同じ壁に当たる。
Runtime Cache に既にある銘柄だけを見る、生成を諦めて手動台帳をテストで縛る、など
**取得を増やさない案を優先し、選んだ理由を報告すること。**

### FU23: FU14 の退避 catch が広すぎる
投信の500を防ぐために入れた catch が、**本来知りたい失敗まで飲み込む**。
握りつぶす対象を「上流の特定の失敗」に絞り、それ以外は落とすこと。
**CLAUDE.md の最優先規約（価格は /api/stock 経由・repairPriceGlitches を通す）に
影響しないことを確認すること。**

### FU26: SAFE に高安を要するパネルが4件混ざっている
tech-adx / tech-breakout / vol-atr / tech-stoch。

**調査は 2026-08-23 に本番で済んでいる（§5①'）。読んでから始めること。**
投信 `0331418A` の `tech-adx` は True Range が |ΔC| に潰れたまま
**ADX 13.64 / +DI 51.54 / −DI 48.46 と、それらしい数値を出して「レンジ相場」と断定する。**
残る3件も同じ理屈（いずれも高安を使う）なので、**4件とも UNAVAILABLE 方向で始めてよい。**
それでも**画面は一度見ること**（§0.5③ と同じ失敗の形を避けるため）。

**S15 のバッジと関係がある（§0.6③）。**
`tech-adx` / `tech-breakout` / `tech-stoch` の3件には S15 がバッジを付けた。
現状の main では投信でもこの3つが SAFE なので、
**偽の ADX から作られたバッジが閉じた見出しにまで出ている。**
UNAVAILABLE に倒すと `AccordionSection` が `summary` を渡さなくなり**自動的に消える**ので
追加のコードは要らない。**消えることを画面で確認すること。**

### FU27: discretionary 節がパネルIDを持たない
DiscretionaryLab を直接描くため AccordionSection の外にある。
