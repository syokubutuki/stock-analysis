## 2. worktree の準備

**未コミットがあると worktree から参照文書が見えない**（ラウンド1で実際に起きた）。
下のスクリプトはその状態なら worktree を作らずに中断する。

> ### ⚠ シェルを間違えないこと
>
> **この環境の既定ターミナルは PowerShell である。下の bash スクリプトを
> PowerShell に貼ると `$dir` / `$br` が展開されず、`$dir` という名前のフォルダと
> `$br` というブランチがリポジトリ内部に作られる**（2026-08-11 に実際に発生）。
>
> - **PowerShell を使うなら → 後述の「PowerShell 版」を使う**
> - bash 版は Git Bash / WSL でのみ使う
>
> どちらで実行したか分からなくなったら `git worktree list` と `git branch` を確認し、
> `$dir` や `$br` があれば下記で除去する:
> ```
> git worktree remove '$dir' --force; git worktree prune; git branch -D '$br'
> ```

### bash 版（Git Bash / WSL）

```bash
cd C:/Users/hikar/next/stock-analysis

if [ -n "$(git status --porcelain)" ]; then
  echo "中断: 未コミットの変更があります。worktree から見えないので先にコミットしてください。"
  git status --short
else
  for pair in "sa-s9:feat/regression-tests" "sa-s10:feat/guide-migration" \
              "sa-s11:feat/post-deploy-verify"; do
    dir="../${pair%%:*}"; br="${pair##*:}"
    git worktree add "$dir" -b "$br" && (cd "$dir" && npm install)
  done
  echo "完了。参照文書の存在を確認します:"
  for d in sa-s9 sa-s10 sa-s11; do
    n=0
    for f in AGENTS.md CLAUDE.md NEXT_SESSION.md \
             docs/site-improvement-execution-plan.md docs/site-improvement-round3.md; do
      [ -f "../$d/$f" ] && n=$((n+1))
    done
    echo "  ../$d : 5文書中 $n 個"
  done
fi
```

### PowerShell 版（この環境の既定シェル）

```powershell
Set-Location C:\Users\hikar\next\stock-analysis

if (git status --porcelain) {
  Write-Host "中断: 未コミットの変更があります。worktree から見えないので先にコミットしてください。"
  git status --short

  $pairs = @(
    @{ Dir = '..\sa-s9';  Branch = 'feat/regression-tests' },
    @{ Dir = '..\sa-s10'; Branch = 'feat/guide-migration' },

  foreach ($p in $pairs) {
    $n = ($docs | Where-Object { Test-Path (Join-Path $p.Dir $_) }).Count
    "  {0} : 5文書中 {1} 個" -f $p.Dir, $n
```

**判明した副次的な事実（未修正・要判断）**

1. **投信名に HTML実体参照が残る（FU13。同日修正済み）。** `03311187` は本番の `name` が
   `eMAXIS Slim米国株式(S&amp;P500)` となり、画面にそのまま出ていた。
   原因は `stock-source.server.ts` の `<title>` フォールバックで、
   HTMLエスケープを解いていないこと。`priceBoard.name` 側の正規表現
   （`yahoo-fund-history.ts:42-44`）はこの銘柄のページ構造に一致せず `null` になり、
   `parseYahooFundPage` が `<title>` 由来の名前をそのまま返していた。
   `0331418A` は `priceBoard.name` に一致するため無傷。**& を含む名前の投信でのみ露出する。**
   **修正**: `decodeHtmlEntities()` を追加し、JWT・RSC 両経路が共有する `fundName` の
   1箇所で解く。JSON由来の名前は元からエスケープされていないので素通りする。
   実体参照の入れ子で二重にデコードしないよう1回の走査で置換し、範囲外のコードポイントは
   原文のまま返す（名前の整形のために価格取得を落とさない）。
2. **JWT経路が「途中で」壊れたときは RSC へ退避しない。** 退避の分岐は
   `stock-source.server.ts:189`（`if (!pageData)`）＝**HTMLに `jwtToken` が無いとき**だけ。
   `jwtToken` はあるが BFF が 403/期限切れを返す形の故障は、退避せずそのまま失敗する。
   F36 の故障が再発する形によっては、R0 の保険が効かない可能性がある。
3. **10年レンジは初回8.0秒**（`0331418A`、Vercelキャッシュ MISS 時）。ページングが
   1リクエスト20件のため約95往復。`Vercel-CDN-Cache-Control: s-maxage=3600` があるので
   2回目以降は HIT。株式（Yahoo chart API 1往復）とは応答特性が違う。
4. 投信は OHLC が全て基準価額と等しく `volume=0`。ローソク足は横線、
   出来高・日中系の分析は無意味な結果になる（バグではなく元データの性質）。

### FU10: 価格の有効桁 — **推奨は「8桁のまま据え置き」**

#### 4. 推奨: **変更しない（8桁維持）**

「統計量への影響が無視できる」ことは確認できたが、**変更の便益が小さく費用が非対称**である。

- **便益**: 10年系列1本あたり 8.8 KB。1銘柄の初回表示で数本取ることを考えても数十 KB。
- **費用1（即時・確実）**: `SANITIZER_VERSION` を 3→4 に上げる必要がある。これは
  クライアント IndexedDB（`price-cache.ts:39`）と**サーバー Runtime Cache のキー**
  （`stock-data.server.ts:52`）を**同時に無効化する**。全銘柄・全期間が一斉に
  コールドスタートし、Yahoo への再取得が走る。**削減した分は当面の再取得で相殺される。**
- **費用2（恒久）**: 「配信値は元データより粗い」という但し書きが1段深くなる。
  価格データの保守性は本プロジェクトの最優先規約（CLAUDE.md 冒頭）であり、
  8桁は「倍精度の情報をほぼ落とさない」と言い切れるが、6桁は
  「統計量への影響は測ったうえで無視できると判断した」という説明を要する。

**P1 で取り分の大半（圧縮後42%）は既に取れている。** 残りの 18.5% のために
規約面の説明責任とキャッシュ全破棄を負う理由は薄い、というのがこの検証の結論である。

**判断を変えうる材料**: 実測の転送量が問題になっている証拠（モバイルの実測・
Vercel の帯域コスト）が出た場合。そのときは **7桁**（brotli −9.7%・相対誤差 2.0e-8）が
中間案として最も安全である。

**P2（段階取得）への含意**: 現状の実転送は10年系列で **47.5 KB**（生JSONの 263 KB ではない）。
段階取得が節約できるのはこの 47.5 KB の一部にすぎない。**見送りを支持する材料**として記録する。
