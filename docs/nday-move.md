# 値動き条件別の将来分布・売買検証（cond-nday-move）

直前 n 営業日の値動きが条件を満たした後について、次の3つを画面上で分けて示す分析。

1. **事後の分布** — 条件成立後、実際にどのような値動きが分布していたか（後から分かった値動きの記述。売買の成績ではない）
2. **実行可能な売買** — 当時の情報だけで実行できる買いのみの規則の成績
3. **頑健性・過剰適合** — その成績が偶然や選び過ぎで説明できないかの点検（擬似アウトオブサンプル）

| 区分 | ファイル |
|---|---|
| パネル | `cond-nday-move`（`conditional` 節「状態 → 先行きリターン」、`cond-rise-to-decline` の直後） |
| 入力 | `input: "all+period+ticker"`（10年フル＋ページの期間＋銘柄＋`StockData.dataQuality`）、`closeOnly: "caution"` |
| 条件・イベント・監査 | `app/lib/nday-move.ts` |
| ① 分布 | `app/lib/nday-move-paths.ts`、Kaplan–Meier は `app/lib/survival.ts`（`rise-to-decline.ts` と共用） |
| ② 売買 | `app/lib/nday-move-trades.ts` |
| ③ 頑健性 | `app/lib/nday-move-robustness.ts`、CSCV は `app/lib/cscv-pbo.ts`（汎用）、Worker は `app/lib/nday-move.worker.ts` |
| 出力・再現 | `app/lib/nday-move-export.ts` |
| 画面 | `app/components/analysis/NdayMove*.tsx`、`ndayMoveShared.tsx` |
| テスト | `app/lib/__tests__/nday-move.test.ts`（合成系列 39件） |

## 0. データ

- 日足は `/api/stock?range=10y` の修復済み系列（`repairPriceGlitches()` を通過したもの）。新しい取得・修復はしていない。
- **価格は配当・分割の調整後**（`stock-source.server.ts`: 終値=adjclose、始値・高値・安値も同じ倍率）。
  - 配当は価格に再投資済みで含まれる → **配当を別途加算しない**（二重計上になる）。
  - 配当額・権利落ち日は API が返さない → **税引後は計算しない**。表示は「税引前・配当込み」。
  - 条件判定も調整後終値なので、権利落ち（銀行株は3月・9月）の機械的な下落で下落条件が成立しない。
  - 円建ての価格は当時の約定値ではない。新しい権利落ちで過去の水準が遡って変わる（比率は不変）。実例：2026-09-30 取得分と 2026-10-01 取得分で 8306.T の過去の終値が最大1.9%ずれていた（9月末の権利落ちの織り込み）。
- 取得は最長10年。持株会社化などで上場した銘柄（7322.T: 2018-04-02、5832.T: 2022-10-03）は上場日からで、前身の銘柄とはつながない。
- **1行＝1営業日**（`rise-to-decline` と同じ規約）。欠損を詰めたり補ったりしない。
- **出来高0で4本値が同値の行**（休場日の擬似行・売買のなかった日）を監査で拾う。8306.T に22行・7322.T に10行（2017〜2018年、すべて東証の休日）。
  - その日の寄りでは約定させない（見送り）。予定の決済日なら次の立会日の終値へ延ばす。
  - 判定区間・観測窓に含む事例には印を付ける。
  - 取得層での除外は別タスク（`Handle phantom holiday rows at the fetch layer`）で扱う。入れば、ここでの局所的な守りは単純化できる。
- 出来高があるのに4本値が同値の行は「値幅制限の張り付きの疑い」として、約定に印を付ける（`suspectFill`）。
- 投信（全バーで4本値が同値かつ出来高0）は①だけを計算し、始値で約定する②③は「不可」と表示する。

## 1. 条件とイベント

### 定義

- 騰落率は次の式で計算する。下落は r ≤ −p、上昇は r ≥ p。閾値ちょうどを含む（許容差 1e−10）。

  ```
  r_t = 100 (C_t / C_{t−n} − 1)
  ```

- σ単位（任意・既定オフ）は次の式で計算する。
  - σ̂ は t−n で終わる60本の日次対数リターンの標本標準偏差で、**判定区間を含めない**。
  - 判定区間を含めると、大きく動いた日ほど z が縮む。

  ```
  z_t = ln(C_t / C_{t−n}) / (σ̂_{t−n} √n)
  ```

### 数え方

- **立ち上がり（既定）**：t日に成立し、t−1日に不成立だった日。
  - データ先頭で t−1 を判定できない日は、立ち上がりか分からないので除外して件数を示す（「判定不能」）。
- **成立日すべて**：成立した日を全部数える。

### 期間（as-of）

- 分析期間 [開始, 終了] は、イベントとして数える日と将来を観測してよい範囲を決める。
- 判定に使う過去（C_{t−n}・前日の判定・σ̂）は期間の開始前にさかのぼってよい（その日に分かっている情報）。
- 将来は終了日で打ち切る。

### 重複除外（①）

- 古い順に採用する。採用日 t の次は t+H+1 以降から探す。
- 実際の値動きで間隔を変えない（未来の結果で標本を選ばない）。
- 除外件数と理由を表示する。

## 2. ① 事後の分布

各事例 t について A = min(H, 終了 − t) を観測できた日数とし、次を求める。

| 指標 | 定義 |
|---|---|
| 経路 | X_{t,k} = 100(C_{t+k}/C_t − 1)、k = 0…A |
| 最高・最低終値の日 | 0…H の argmax / argmin。**0日目を含み、同値は最初の日** |
| 最高・最低の変化率 | X_{t,k^max}, X_{t,k^min} |
| 初めて前日終値を下回る日 | min{k≥1 : C_{t+k} < C_{t+k−1}}（同値は下落ではない） |
| 最高値から q% 反落する日 | M_{t,k} = max_{0≤j≤k} C_{t+j}、min{k≥1 : 100(1 − C_{t+k}/M_{t,k}) ≥ q} |
| 翌朝の窓 | 100(O_{t+1}/C_t − 1)（②の売買には取れない部分） |

- 極値と分位帯は**H日を完全に観測した事例だけ**で作る。末尾の観測不足は一覧に残し、極値を「暫定」と表示して分布から除く。
- 「初めて下がる」「q%反落」は期間内に起きない事例がある。
  - 右打ち切りとして Kaplan–Meier で累積到達確率を出す。
  - 同日の発生と打ち切りはその日のリスク集合に含める。
  - 尽きた先は外挿しない。
- H日目の極値は「観測窓の端」と明示する（反転の確認ではない）。
- 日別の中央値の線は実在の経路ではない。そのことを示すため、中央値の線に最も近い実在の事例（二乗距離最小）を重ねる。
- 無条件の比較基準：期間内で判定できる最初の日から、完全窓を取れる全営業日を起点にした分位帯。
- 層別（記述のみ・有意性は主張しない）：
  - 事前ボラの三分位（判定区間より前の60営業日）。
  - 市場との連動：同じ n 日に ^N225（米国株は ^GSPC）が銘柄の騰落の半分以上、同じ向きに動いたか。

## 3. ② 実行可能な売買

### 約定と保有

- t日の終値で判定 → **t+1 営業日の始値で買う**（保有1日目）→ **保有 h 日目（t+h 日）の終値で売る**。
- h=1 は同じ日の寄り→引け。
- 同一銘柄で建玉は1つ。保有中のシグナル（t′ < 決済日）は無視して件数を数える。決済日の引けのシグナルは翌日に建ててよい。
- 期間末のシグナルは翌営業日が無いので約定しない（件数に残す）。
- 期間末に保有中なら「未決済」：
  - 最終日の終値の清算価値（売りの費用を控除）で評価する。
  - 資産曲線には含め、確定取引の統計には入れない。

### 資金

- 初期資金（既定100万円）× 投入比率（既定100%）。
- 売買単位：0＝端数株（既定）、または100株単位など。単元に満たなければ見送る。
- 待機資金の利息は0%。

### 費用

- 片道 c = 手数料% + スリッページ%（既定 0 + 0.05%）を、買いと売りの両方に資産×(1−c) で掛ける。
- 1往復の対数控除は 2 ln(1−c)。近似ではない。
- 買い持ちも期首と期末で1往復分を払う。

### 成績の計算

- 1回の損益は次の式で計算する。

  ```
  R = (1−c)² C_{t+h}/O_{t+1} − 1
  ```

- 資産曲線は待機資金を含む日次の時価評価。
- 年率は資産曲線の幾何成長（暦日で年数換算）。**取引平均×回数で年率化しない。**
- シャープは日次対数リターン×√252（待機日0を含む）。
- 最大ドローダウンは時価評価で計算する。
- 投資していた期間の割合は、建玉を持っていた日 ÷ 全日。

### 比較の物差し（資金制約のある戦略成績と分けて表示する）

- **買い持ち**：口座を開いた日以降で最初に約定できる日の寄りで全額を買い、期末に清算する（同じ日・同じ初期資金）。
- **損益分岐の片道費用**：
  - 1回の平均が0になる c* = 1 − exp(−ḡ/2)。
  - 全額・端数株のときだけ、買い持ちと並ぶ c* = 1 − exp((G_BH − Σg)/(2(K−1)))。
- **予測力（資金制約なし）**：
  - シグナルの日すべてと、期間内の全営業日を起点に、同じ「翌日寄り→h日目引け」1回分を比べる。
  - 平均の差の95%区間は、営業日の並びを max(h,21) 日ずつ束ねた移動ブロック・ブートストラップ（1000回・シード固定）で出す。
  - 差を2標準誤差で見分ける件数の目安 (2s/|D|)² も示す（独立を仮定した下限）。
  - **独立を仮定した p 値は出さない。**
- **無作為タイミング（プラセボ）**：
  - 同じ件数・同じ h・重ならない規則で、建てる日だけを無作為にする（逐次配置・1000回・シード固定）。
  - 実際の成績（確定取引の Σ対数）の百分位を示す。
  - 露出を揃えた対照で、買い持ちとの差のうち「市場にいた日数」の分を取り除いた後のタイミングの価値を測る。

## 4. ③ 頑健性・過剰適合

### 候補格子

- 既定は 方向{下落, 上昇} × n{3,5,10,20} × p{3,5,7,10}% × h{3,5,10} ＝ 96通り（σ単位なら p{1,1.5,2,2.5}）。
- **全件**を同じ費用・同じ資金規則・**共通の評価期間**で評価し、台帳に残す。
  - 評価期間は、最大の n でも判定できる日の翌日から。
  - 候補ごとに開始日がずれると、成績差に期間差が混ざり、CSCV の前提（同じ日付の行列）も崩れる。
- 表示：ヒートマップ（n×p、方向×h ごと）、全件の表（既定は格子順。最良順に固定しない）、シャープが正の候補の割合、中央値、同期間の買い持ち。

### 試行の記録

- 画面で手で試した条件（方向・n・p・単位・数え方・H・h の組）を、端末の localStorage に銘柄ごとに記録して数を出す。
- `test-registry.ts` の多重検定台帳にも96通りを計上した。

### 選び過ぎの水増しの目安

- SE·√(2 ln N)（SE＝現在の条件の取引1回の標準偏差/√件数、系C26）。

### 近傍

- 同じ方向で n・p・h のどれか1つだけを1段ずらした候補と、そのシャープの中央値。

### ウォークフォワード（暦年・拡大窓）

- 各年 Y について、訓練＝評価開始〜Y−1年末（最低3年）。
- 訓練では**決済が訓練末を越える取引を建てない**（境界パージ。検証期間の値動き・損益が訓練に漏れない）。
- 選択：
  - 訓練の確定取引が最低件数（既定10）以上の候補のうち、日次シャープ（待機日0・費用込み）が最大のもの。
  - 正の候補が無ければ「取引しない（現金）」。
  - 同点は格子の並びで先の候補。
- 検証：
  - 選んだ規則を Y 年に固定する。前年末の引けのシグナルから新しい規則が効く。
  - 期をまたぐ建玉は、建てた期の規則で満期まで持つ（建玉は1つ）。
- 各期の表示項目：選んだ条件・選択可能な候補数・訓練の取引と成績・検証の取引と口座の対数成長・同期間の買い持ち。
- 検証期間をつないだ1本の口座の資産曲線を、同期間の買い持ちと並べる。
- 名称は「**擬似**アウトオブサンプル」。格子・既定値は全期間を見た設計者が決めているため。

### CSCV による PBO

原論文（Bailey, Borwein, López de Prado, Zhu, *The Probability of Backtest Overfitting*）の Algorithm 2.3 に従う。

- 行列 M：共通期間の日次対数リターン（T行）× 候補（N列）。待機日は0、費用込み。
- 行を S 個（既定16）の連続した等しい塊に分ける。端数は古い側から落とす。
- S/2 個を訓練・残りを検証とする全 C(S,S/2) 通り（S=16 で12,870通り。論文本文の12,780は誤植）で、訓練シャープ最大の n* を求める。
- 検証での相対順位とロジットは次の式で計算する。順位は昇順で最良が N、同順位は平均順位。

  ```
  ω̄ = r̄_{n*}/(N+1),  λ = ln(ω̄/(1−ω̄))
  ```

- **PBO = #{λ ≤ 0} / 組合せ数**。
- 別の指標として並べるもの（PBO の代用にしない）：
  - 損失確率 P(検証シャープ<0)
  - 性能劣化（訓練 vs 検証の散布と傾き）
  - 確率優越（n* の検証成績と、無作為に1つ選んだ場合の分布の累積分布）
  - n* に選ばれた回数
- **前提を満たさなければ計算せず、理由を表示する。**
  - 1塊20営業日以上で S≥8 が取れること（取れる最大の偶数 S に下げる）。
  - 候補の取引件数の中央値が20以上。
  - 中身の異なる候補が10以上。
- 注意として明記すること：
  - PBO は「格子から最良を選ぶ手順」の評価で、個別の条件の勝率ではない。
  - PBO を条件選びの目的関数に使わない。
  - 試した候補がすべて台帳に載っている前提。
  - 塊の境界をまたぐ保有・系列相関は完全には切れない。

### 利益の集中（現在の条件の確定取引）

- 年別の取引数と Σ対数。
- 上位1/3/5回を除いた累積。
- 上位10%の取引が利益に占める割合。
- 1年ずつ除いた累積の範囲。

### 計算の置き場所

- ③は Web Worker で計算する。
- 進捗を約100msごとに返す。
- キャンセル＝terminate して作り直す。
- reqId で古い応答を捨てる。
- 条件（格子・費用・資金・期間・データ）が変わったら「前の条件の結果」と表示し、再計算を促す。

## 5. 再現（保存・出力）

- **JSON**の内容：
  - 機能の版
  - 銘柄
  - `SANITIZER_VERSION`
  - `dataQuality`
  - 取得した全期間と分析期間の初日・最終日・本数・**指紋**
  - 全パラメータ・格子・ウォークフォワードと CSCV の設定・乱数シード
  - ①②③の結果（③は書き出し時の条件で計算済みのときだけ）
  - 手での試行数
  - 注記
- **指紋**は日付と前日比の対数（10⁻⁶ で丸め）の FNV-1a。
  - 水準の遡及調整（全体の定数倍）には動じず、行の欠落・値の書き換えには反応する。
  - 新しい権利落ちが分析期間に入ると、その日の比率が変わるので指紋も変わる。正しい挙動で、「同じデータではない」と知らせる。
- **CSV**：イベント一覧・取引一覧・候補台帳。BOM 付き・RFC 4180 の引用。
- **読み込み**：JSON から条件を復元する。銘柄・期間・指紋が違えば警告する。

## 6. 既存の分析との関係

| 既存 | 違い・扱い |
|---|---|
| `event-study.ts`（`causal-event`） | 1日の対数リターンで判定・毎回数える・対数累積。**触らず別の分析**として残す |
| `rise-to-decline.ts`（`cond-rise-to-decline`） | 上昇のみ・成立日すべてが起点・最高値の日は0日目を除く・既定 H=20。残して隣に置き、Kaplan–Meier だけ `survival.ts` に切り出して共用（同パネルの黄金値テスト13件は不変） |
| `walk-forward.ts`（`edge-walkforward`） | その「PBO」は「フォールドのうち選抜シグナルの検証順位が中央値未満だった割合」の簡易推定で CSCV ではない。パージも無い。ここでは流用せず、CSCV を `cscv-pbo.ts` に新設した |
| `strategy-vs-benchmark.ts` | 終値→終値の建玉が前提で、翌日寄りの約定を表せない。費用を対数空間で厳密に控除する規約と回転率の併記は踏襲した |

## 7. 検証

### 数値テスト（`npm test`・合成系列）

- **条件**：立ち上がり／成立日すべての区別、閾値ちょうど、データ先頭の判定不能、as-of（開始前の過去を判定に使う）、重複除外の範囲、σ̂ が判定区間を含まないこと。
- **監査**：投信型、出来高0の擬似行、4本値同値、壊れた日付。
- **①分布**：
  - 経路・極値（同値は最初の日・0日目を含む・H日目の端）、前日割れ（同値は除く）、q%反落、翌朝の窓。
  - 観測不足の事例の扱い（一覧に残し分布から除き KM で打ち切り）、無条件の起点数、投信型。
  - **未来の価格を書き換えても前の事例が変わらない**こと。
- **②売買**：
  - 売買日のずれ（t→t+1寄り→t+h引け、h=1 は同日）。
  - 費用（独立の式 (1−c)^{2K}·Π と照合、買い持ちの1往復）、損益分岐。
  - 保有中の無視と決済日の引けでの再エントリー、期末の未決済。
  - 約定不可日の見送りと決済の延長、期間末のシグナル、単元株と資金不足。
  - **未来を書き換えても前の取引・建玉判断・資産が変わらない**こと。
  - シード固定での再現性。
- **③頑健性**：
  - 格子の展開。
  - **ウォークフォワードで検証期間以降の価格を書き換えても、その期の選択が変わらない**（漏れなし）。
  - 境界パージ、共通期間、標本不足時に PBO を出さないこと、集中、近傍、水増しの目安。
- **CSCV**：
  - 手計算（N=2・S=2 で ω=1/3・λ=ln(1/2)・PBO=1）、組合せ数と端数の落とし方。
  - 全候補が同一なら PBO=1（λ≤0 の定義による）。
  - 植え込んだ優位で PBO<0.1、優位の無い40データの平均 PBO が0.4〜0.6。
- **出力**：指紋の不変性・感度、CSV の引用、JSON の往復と警告。
- **全体**：258件すべて合格（追加39件を含む）。

## 8. 未対応事項・既知の限界

- **税引後**：配当額・権利落ち日を取得していないため未対応。課税口座では往復ごとの実現益課税で買い持ちとの差がさらに開く（系C23）。
- **利確・損切り**：出口は時間決済のみ。
  - `simulateAccount` は出口を差し替えられる形にしてある。
  - 実装時は `weekday-barrier.ts` の方式に揃える：同じ日足で両方に触れたら不利側と有利側の帯で示し、寄りで逆指値を越えたら寄りで約定。
  - 終値で判定する出口は翌日寄りで約定させる。
- **建玉の重複**：「保有中は無視」のみ。積み増し・保有延長は未対応。
- **複数銘柄の横断比較**：未対応。行うなら、比較期間の違いの明示と、日付クラスタで扱う推論（`intraday-basket.ts` の `clusterStat`）が要る。同業の銘柄はそろって動く。8306.T の下落事例の半数は 7322.T と±7日以内に重なる。
- **前向きの検証**：条件を凍結して今後のデータだけで採点する仕組み（`prospective-ledger` は `EdgeSeries` 前提）への登録は未対応。本当に未見のデータはこれだけ。
- **約定の現実**：
  - 寄りの約定値＝始値と仮定しており、成行の板寄せでの約定は日足では確かめられない。
  - 値幅制限の張り付きは印のみ。
  - 出来高に対する注文の大きさ（市場インパクト）は見ていない。
- **擬似行**：1行＝1営業日の規約のため、擬似行を含む区間は実際の立会日数とずれる（印で開示）。取得層での除外は別タスク。
- **データ期間**：API の上限10年。8306.T などは Yahoo にもっと長い履歴があるが、範囲の拡張は全パネルとキャッシュに影響するので行っていない。
- **CSCV**：塊の境界をまたぐ保有と系列相関を完全には切れない。候補の取引が少ない（中央値20未満）と計算しない。
- **既存の型エラー**：`app/lib/__tests__/tiers.test.ts:101` の型述語（`s is string`）が `tsc --noEmit` で1件エラーになる。この変更以前からあり、`next build` は通る。
