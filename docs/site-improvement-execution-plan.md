## グループQ: 表示の正確さ（信頼の土台）

### Q1. 数値フォーマットの統一

**目的**: 精度を売る製品として、桁の不揃いによる信頼低下をなくす。

**根拠**: F30（`現在値 2,914.5` に対し `期間始値 3,452.592`）。
原因は `app/page.tsx:1477-1481` が配当調整済み終値に `toLocaleString()` を素通ししていること。

**現状**: 共通フォーマッタが存在しない。`toFixed` は 2,281箇所（F20）に散在。

**制約・設計意図**:
- **スコープを `SummaryCard` の呼び出し4箇所に限定する。** 2,281箇所の `toFixed` には触れない。
  各分析パネルの桁数はその分析の文脈で決まっており、統一すべきものではない。
- 通貨は `StockData.currency`（`app/lib/types.ts:16`）で判別できる。JPY と USD で妥当な桁は異なる。
- 低位株・低位投信が存在しうるため、**固定小数桁は避け、有効数字ベースを推奨**する
  （0.0012 のような値を 0.00 にしてはならない）。

**受け入れ条件**:
1. 同一カード群の中で桁数の表現が一貫している（例: 現在値と期間始値が同じ規則で表示される）
2. 1円未満の値でも有効な桁が残る
3. `npm run build` 通過
4. 7203.T / 8306.T / 米国株1銘柄 の3つで目視確認。
   **投信は現在価格取得が壊れている（F36）ため確認できない。**
   R0 完了後に投信でも再確認すること（未確認である旨を PR に明記する）

**依存**: なし（単独で着手可能）。ただし投信での検証は **R0 待ち**。

**不確実性**: 「妥当な桁」の定義は銘柄種別によって割れる可能性がある。
迷う場合は「通貨のminor unit + 有効数字下限」の併用を検討し、判断を PR に書き残すこと。

### Q2. 日本語フォントの指定

**目的**: 日本語サイトとしての表示品質を、環境差に依存しない状態にする。

**根拠**: F34（`globals.css:16` が `Arial, Helvetica, sans-serif` のみ。日本語が1文字も無い）。
現状、日本語はブラウザ既定にフォールバックし、Windows / macOS / Android で別書体になる。

**現状**: `next/font` 未使用。`globals.css` は37行でトークン定義も無い。

**制約・設計意図**:
- 数値の可読性が最優先の製品なので、**等幅数字（`font-variant-numeric: tabular-nums`）を

# 6. 全項目に共通する制約

**以下は AGENTS.md / CLAUDE.md / 既存 docs から抽出した、破ってはいけない制約である。**

## 6.1 価格データ（最優先・CLAUDE.md）

- 価格は必ず `/api/stock` 経由。Yahoo Finance を直接叩かない
- 修復は `app/api/stock/route.ts` が通す `repairPriceGlitches()` が唯一の地点
- ベンチマークは `useBenchmarkPrices(ticker)`
- 別の外部データ源を足すなら、その route handler でも `repairPriceGlitches()` を通す
- **判定・閾値・配信表現を変えたら `SANITIZER_VERSION` を上げる**（IndexedDB キャッシュ破棄。→ P1）
- 手を入れたことは画面に開示する（`DataQualityNotice` / `StockData.dataQuality`。→ U4）
- `app/lib/price-sanity.ts` 冒頭の設計思想と過去の誤検出事故を、触る前に読むこと

## 6.2 チャート（CLAUDE.md）

- 横軸が時間・日付の系列は `lightweight-charts` を標準とする
- Canvas2D は横軸が時間でない静的図（分布・散布・QQ・相関行列・位相空間・ネットワーク）のみ
- lightweight-charts v5: マーカーは `createSeriesMarkers`。`series.setMarkers()` は廃止済み
- `LineWidth` は整数のみ（1,2,3,4）

## 6.3 分析コンポーネント（CLAUDE.md / AGENTS.md）

- 新しい分析には `AnalysisGuide` を必ず付ける（7点セット: 概要・数式・用語定義・比喩・読み方・活用・限界）
- 分析コンポーネントは `next/dynamic` の `ssr: false` で読み込む
- 数式・計算は `app/lib/` に置き、UI 内で重複実装しない

## 6.4 収益・法務（`app/lib/tiers.ts`）

- 課金対象は「計算の広さ・期間の長さ・横断・保存/エクスポート」に限る
- **売買推奨を有料機能にしない**（金商法上の無登録助言に触れる）
- **検証基盤は無料側に置く**（ヌル較正・ウォークフォワード・検出力・エッジ減衰・多重検定台帳）
- 既に無料で公開しているものを有料側に移さない

## 6.5 互換性（本書で新たに特定）

- **パネルIDを変更しない。** B-1 で共有されたURL（`?panel=...`）と
  localStorage の `sa:open:<id>` が壊れる（→ M3・U5）
- **`sec=` の値を変更しない。** 同上（→ U5）
- URL優先・localStorage 従の復元順序を維持する
- 「銘柄を変えても開いている分析集合を維持する」は意図的な仕様。退行させない（→ U2）

## 6.6 コミット・PR（AGENTS.md）

- コミットメッセージは日本語で、成果と理由を具体的に（例: `価格修復を取得層に一元化: βの破損を防止`）
- 1コミット1目的
- PR には目的・対象分析・検証コマンド・データ品質への影響を記載。表示変更には比較スクリーンショット
- **`git add -A` を使わない**（ユーザーの並行作業を巻き込む。パスを明示して add する）

# 9. やってはいけないこと

`asset-utilization.md` §5 と、本書の調査から追加したもの。

## 既存文書からの禁止事項

- **ガイド本文を手でコピーしてページ化する** — 二重管理になり必ず片方が腐る。
  データに分離して1ソースで両方描く（→ R2）
- **ガイド本文を AI で薄く増やして量産する** — thin content 判定でドメイン全体が沈む。
  現在の価値は「7点セットが全部埋まっている密度」にある
- **`app/lib` を全部OSSにする** — 基礎層と固有層を分けずに出すと差別化を配ってしまう
- **すでに無料で公開しているものを Pro の壁の内側に移す** — `tiers.ts` の方針と既存利用者の信頼を壊す
- **Null result を「でも実はこう使えます」と救済する** — 救済した瞬間に差別化が消える
- **公開トラックレコードをデータが溜まる前に作る** — 最低1年待つ。
  薄い数字を「実績」と称することは、このサイトが最も批判している行為そのもの

## 本書で追加する禁止事項

- **`text-gray-400` の無条件一括置換**（896箇所。暗色背景上では現状が正しい → A1・§1.3 訂正3）
- **`toFixed` 2,281箇所への一括介入**（各分析の桁数は文脈で決まる。Q1 は SummaryCard 4箇所に限定）
- **価格の配信表現を変えて `SANITIZER_VERSION` を上げないこと**（キャッシュ混在で数値が食い違う → P1）
- **パネルID・`sec=` の値の変更**（共有URLと localStorage が壊れる → M3・U5・§6.5）
- **「銘柄を変えても開いている分析集合を維持する」仕様の退行**（意図的な設計 → U2）
- **289本のガイドを「機械的に自動生成できる」前提で計画すること**（→ §1.3 訂正2）
- **前向き検証台帳を「localStorage にある」前提で計画すること**（Postgres へ移行済み → §1.3 訂正1）
- **U1 で全パネルを事前計算すること**（`CollapsibleAnalysis` が意図的に防いでいる負荷が戻る）
- **R1 で中身の薄い銘柄ページを量産すること**（thin content）
- **`git add -A`**（並行作業を巻き込む）
