# 東証休場日の「幻の行」— 実測・除去規則・誤検出分析・影響

2026-10-01。実装: `app/lib/tse-calendar.ts`（休場日表）・`app/lib/price-sanity.ts`
（`removeClosedDayRows` / `repairPriceGlitches(prices, { ticker })`）。`SANITIZER_VERSION` 3 → 4。

## 1. 現象（実測）

本番の `/api/stock?range=10y`（https://kabugenron.com）で `app/lib/universes.ts` の全175銘柄＋
ベンチマーク・米国・為替など16系列を取得した（2026-09-30。404 の6本を除く185系列）。
「出来高0・四本値がすべて同じ・終値が前日終値と同じ」行を数えた。

| 年 | 行数 | 内訳 |
|---|---:|---|
| 2016 | 2 | 3549.T の 2016-11-17/18（平日。上場の付け替え直後） |
| **2017** | **972** | 2017-07-17〜11-23 の休場日 6日 × 東証系列 約162本 |
| **2018** | **2617** | 休場日 16日 × 東証系列 約164本 |
| 2019 | 2 | 6645.T 2019-03-11・4523.T 2019-03-25（平日） |
| 2021〜2025 | 4 | 5844.T 2023-09-29・7276.T 2024-03-29（平日）、^TNX 2件（米国債の休日） |

- **2017-07-17〜2018-12-31 の東証休場日 22日**にだけ集中している。22日は当該期間の平日の休場日の
  **すべて**で、それ以外の日付には1件も無い。2017年前半・2019年以降の休場日には行が無い
  （配信元の一時期の不具合と見られる）。
- 当時上場していた東証系列（株式・ETF）は**例外なく**持っている（22行が159本、上場時期・欠落で
  21行以下が6本）。2019年以降に上場した銘柄（4443/4477/4478/5830/5831/5832/7337/7380.T）には無い。
- 曜日の内訳: 月13・火1・水2・木2・金4。休場の月曜（海の日・敬老の日・体育の日・成人の日・振替休日）が多い。
- **^N225** は 2018-07-16（海の日）の1行だけで、形が違う: **前営業日の行の丸写し**（四本値は前日のまま、
  出来高だけ0）。終値は前日と同じ。
- **米国の株式・指数（^GSPC・^IXIC・^DJI・SPY・QQQ・AAPL・MSFT）には同じ現象は無い**。
  ^TNX には米国債市場だけが休みの日（コロンブス・デー、退役軍人の日）に出来高0の行があるが、
  株式市場は開いている日で別の現象（値が前日と違う行も多い）。本件の対象外。
- 為替（USDJPY=X）・^VIX・^SOX は出来高0が常態。投信は別経路（基準価額・出来高0）。

## 2. 休場日表と配信データの照合

休場日は価格データと独立に持つ（`tse-calendar.ts`）。祝日法の規則（ハッピーマンデー・春分/秋分の
近似式・振替休日・国民の休日）で算出し、法律で個別に動いた日（2019 の即位関連、2020/2021 の五輪移動）と
祝日でない終日休場（2020-10-01 arrowhead 障害）を特例表で持つ。

東証系列 174本の 2016-10〜2026-09 で照合した:

- 配信に行が無い平日 ＋ 幻の行の日 ＝ 休場日表の平日、が**過不足なく一致**（169日）。
  例外は 1321.T・1570.T の 2025-10-24 欠落だけで、これは配信側の欠損（他の172本には行がある）。
- 休場日表の日付にある行で「幻の行の形」をしていないものは **0件**。

`tse-calendar.test.ts` はこの観測（7203.T から規則を使わずに集めた169日）を正解として固定している。

## 3. 除去規則

次を**すべて**満たす行だけを除く:

1. 系列が東証の暦に従う: `.T`（株式・ETF・REIT）と `^N225`・`^TPX`
2. その日付が東証の休場日（`tseClosureReason(time) !== null`。週末を含む）
3. 出来高0 かつ 終値が直前に残した行の終値と同じ（相対 1e-6。調整後終値の浮動小数点誤差だけを吸う）

3 を「四本値フラット」ではなく「出来高0・終値据え置き」にしたのは ^N225 型（前日の丸写し）も同じく
「新しい情報を何も持たない行」だから。連休（1/1〜1/3）は直前に**残した**行と比べるので3連続でも同じ立会日に遡る。

報告（値は書き換えない）:

| 状況 | 扱い | `sessionSuspects.kind` |
|---|---|---|
| 休場日なのに出来高 > 0 か終値が動いている | 残す・要目視（警告色） | `closedDay` |
| 立会日なのに出来高0・終値据え置き（`.T` のみ） | 残す・告知のみ | `zeroVolume` |
| 系列の先頭行が休場日（比べる直前の行が無い） | 残す・要目視 | `closedDay` |

## 4. 誤検出分析 —「出来高0・値動きなし」だけで消してはいけない理由

同じ形の行が**本物の立会日**にも出る。今回の計測で見つかった平日の出来高0・据え置き行:

| 銘柄 | 日付 | 翌立会日 | 解釈 |
|---|---|---|---|
| 4523.T エーザイ | 2019-03-25（月） | 2019-03-26 寄り −20% | 前営業日から売り気配のまま売買不成立 |
| 6645.T オムロン | 2019-03-11（月） | 2019-03-12 寄り +21% | 買い気配のまま売買不成立 |
| 7276.T 小糸製作所 | 2024-03-29（金） | 2024-04-01 寄り +25% | 同上 |
| 5844.T 京都FG | 2023-09-28/29 | 2023-10-02 上場 | 持株会社化の付け替え前後 |
| 3549.T | 2016-11-16〜18 | — | 同上（付け替え直後） |

エーザイの行を消すと、翌日の −20% の窓が前日（3/22）の終値からの値動きに繰り上がり、
**売り気配で売れなかった日に売れた**ことになる。売買シミュレータ・バリア（TP/SL）・ギャップ分析はこの差を
そのまま結論にする。純粋な「出来高0かつフラット」規則はこの5件を全部消す（＝正しいデータの書き換え）。
休場日表を一次の証拠にすると、これらは条件2で落ち、`zeroVolume` として告知だけされる。

ほかの誤検出の経路と、それを塞いでいる条件:

- 投信（基準価額・出来高0が常態）・為替・^VIX・^SOX → 条件1（系列の暦）
- 流動性の低い東証銘柄の売買不成立日 → 条件2（立会日なので消さない）
- 休場日表の誤り（例: 特例の祝日を知らない） → 表に無い休場日は「立会日」扱い＝幻の行を**見逃す**側に倒れる。
  逆向き（立会日を休場日と誤る）は 2016-10〜2026-09 の照合で0件。将来の年で起きても条件3が守る:
  本物の立会日は出来高を持つので、出来高0・据え置きの行（売買不成立）でない限り消えない。
- 日付ずれ（タイムゾーン変換の誤り等）で本物の立会日が休場日に載る → 出来高・値動きがあるので条件3で残り、
  `closedDay` として警告される。

## 5. 開示

- `StockData.dataQuality.removedClosedDays`（日付・休場の理由・配信値）と `sessionSuspects`。
  版3以前のキャッシュでも読めるよう省略可能。`SANITIZER_VERSION` を 4 に上げたので IndexedDB と
  Runtime Cache（キー `s4`）は旧版を捨てる。
- `DataQualityNotice`: 除去・売買不成立の告知だけなら落ち着いた色（sky）。東証銘柄のほぼ全部に常時出るので、
  警告色にすると警告そのものが読まれなくなる。`closedDay` と未修復ジャンプは従来どおり警告色。
- `hasSanityWarnings()` が false の告知は「基本」節の詳細パネルを自動展開しない（破損ゼロでもパネルが
  最上段を占めていた頃に戻さないため）。
- `DataQualityPanel`: 除去した行（銘柄ごとに折りたたみ）と、売買不成立日・休場日の異常行の表。ガイドに 4b 節。
- `/portfolio`: 除去のあった銘柄数と総行数を1行で集約。

## 6. 数値が変わる分析（実測・除去前 → 除去後）

価格の水準は変わらない（幻の行は前日の据え置きで、翌立会日のリターンは除去前後で同じ）。
変わるのは「行＝立会日」を数える計算。7203.T / 8306.T / 1306.T の10年日足（2461行 → 2439行）:

**曜日の終値リターン（10年）** — 平均・t はほぼ不変、n と0リターンの数が変わる。
月曜の n は 461 → 448、リターンちょうど0の月曜は 18 → 5（7203.T）・14 → 1（8306.T）。
2017-07〜2018-12 に限ると 7203.T の月曜 79日のうち 13日（16%）が休場日の偽の月曜（リターン0）で、月曜のσを 1.23% → 1.12% と過小に見せていた。

**休場コンテキスト（`session-gap.ts` / SessionGapChart）** — 連休前・連休明けの判定が 105 → 123 日（+17%）。
幻の行があると祝日の月曜が立会日に見え、火曜が「通常の火曜」に、金曜の祝日前の木曜が「通常の木曜」に化けていた。
最も直接に結論が変わる分析。

**曜日トレード・シミュレータ（`weekday-trade.ts`）**（複利累積）:

| 戦略 | 7203.T | 8306.T | 1306.T |
|---|---|---|---|
| 月寄→金引 ロング | 77.1% → 69.7%（445 → 429回） | 324% → 287% | 99.3% → 84.4% |
| 金引→月寄 ロング（週末ギャップ） | 93.5% → 101.8% | 143% → 167% | 94.2% → 109.9% |

休場の月曜の「始値」＝前週金曜の終値で建てていたため、月曜寄りエントリーは連休明けの窓を**ただで**取っていた
（実在しない約定）。週末ギャップ側は逆に、休場の月曜で「寄りで手仕舞い」＝リターン0の往復を数えていた。
曜日ワークベンチ・NISA vs 課税・Weekday vs B&H・ヌル較正・最適手仕舞いなど `runStrategyTrades` /
`computePlan` を使う分析は同じ向きにずれていた。

**週末プレミアム（`weekend-premium.ts`）** — 7203.T の μ_w 0.035% → 0.023%・片側p 0.275 → 0.349、
Sharpe 差 −0.034 → −0.002。結論（μ_w≈0・非有意）は変わらない。

**N営業日の窓** — 10年の20行窓の 12% が幻の行を含んでいた（＝実際は19営業日分のリターン）。
前向きリターン分布・保有期間 h・ローリング窓の統計が影響を受ける。

β・σ・相関などのリターン系の統計は、0リターンの点が22個抜けるだけなので変化は小さい（n が 1% 減る程度）。

## 7. 未対応・後続

- `feat/nday-move`（値動き条件別の将来分布・売買検証）は、本修正が入るまでのローカル対策
  （出来高0の足では約定しない・影響事例にフラグ）を持つとされる。取得層で休場日の行が消えるので、
  **「休場日の行」への対策としては不要になる**。ただし「出来高0の足では約定しない」は売買不成立の立会日
  （§4 の表）にも効く正当な規則なので、消さずに残すのがよい。フラグは `dataQuality.sessionSuspects`
  （`zeroVolume`）へ寄せられる。※ 本ドキュメント作成時点でそのブランチは main と同じコミットを指しており、
  作業ツリーも見つからなかったため、コードは確認できていない。
- 日中足（`/api/intraday`）には適用していない（休場日に分足は配信されない）。
- ^TNX の米国債休日の行は別現象として未対応（株式市場は開いているので、米国の取引所暦で消すと誤り）。
- 休場日表は 2099 年まで規則で算出するが、将来の特例の祝日は知らない。新設されたら `SPECIAL_HOLIDAYS` に足す。
