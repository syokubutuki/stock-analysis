### FU41 — 一括開放とバッジの寿命を分けた

`AccordionSection` の React key から `summaryScope` を外し、鍵を2つに分けた。

| 鍵 | 値 | 決めるもの |

できたのは「原因の機構を除いたこと」と「ボタンが出た瞬間に押しても 300ms / 1s / 3s 後に
7件とも開いたまま」の確認までである。**「直った」と断定していない。**

### FU35 — 要約を per-panel 購読へ

Context に Map を載せる方式をやめ、`useSyncExternalStore` でパネルごとに購読する
`AccordionPanel` を挟んだ。**Context の値は scope が変わるときしか変化しない。**

**設計上の注意（消すと静かに壊れる）:** `reportResultSummary` の識別子を `summaryScope` に
紐づけてあるのは意図的である。scope が変わると必ず effect が再実行され、捨てられた要約が
その場で報告し直される。**安定化させると「銘柄をまたいで同じ判断になるパネル」だけ
バッジが静かに出なくなる。** コード中にもコメントで残した。

要約は「記録した scope とセット」で持つので、まとめて捨てる操作を持たない。
持つとレンダー中（純粋でない）かエフェクト中（子の報告より後に走って消してしまう）の
どちらかで呼ぶことになる。React Compiler の lint（`react-hooks/refs`）もレンダー中の
ref 参照を**エラー**で止めるので、この形しか取れない。

### FU27 — `discretionary` は `render: "workspace"` 種別

擬似パネルIDを作っていない。テストで固定してある:

- `discretionary` の `render` が `"workspace"`・`groups` が空・`Workspace` が登録されている

## 8. 判断が割れうる箇所・次への申し送り

- **パネル本体が銘柄変更で再マウントされなくなった。** S17 の key が入る前（2日前まで）の
  挙動に戻っただけだが、マウント時にしか props を読まないパネルがあれば古い値が残りうる。
  `7203.T` → `8306.T` → `6758.T` → `9432.T` で見た範囲では問題なし。**全パネルは見ていない**
- **分類の内訳（78/24/149）と `distribution 12/16` などの比率をテストで固定値にした。**
  パネルを増やすと落ちる。意図的な更新を強制する側に倒してある。緩めたいなら判断が要る
- **FU24 はレジストリの1フィールド（`input`）として入ったが、UI は節単位のまま。**
  「節の中で実際に反応するのは一部」という事実は `seriesAwarePanelCount()` とテストで
  可視化したが、セレクタの見せ方を変えるのは設計判断なので M3 の外に置いた
- **FU29 は `ink` と `grid` の2つだけを縛った。** `surface` は「相当」であって同値ではないため、
  一致しないことを固定してある。対応表を格上げするなら判断が要る
