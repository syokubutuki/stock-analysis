# as-of 検証（過去の時点に戻って判断を採点する）

新セクション `as-of検証`（`app/page.tsx` の `asof`）。2026-07-31 実装。

## 何を解いたか

バックテストの大半は「戦略の損益」を測る。しかしこのアプリが画面に出しているのは建玉ではなく
**判断**である——方向(up/down/flat)、上昇確率、予測レンジ、ボラ予測、変化点警告。
これらは「儲かったか」では採点できない。確率には確率の、区間には区間の、
ボラ予測にはボラ予測の正しい採点則がある。

そこで「過去の任意の時点に戻り、その時点で分かる情報だけで出した判断が
その後に適切だったか」を、型ごとの採点則で判定する仕組みを作った。

## 先読みが入らない理由（この設計の土台）

`computeDigest(prices, …)` と `computeForecastRange(prices, …)` は
**渡された配列の外を一切参照しない純粋関数**である。したがって `prices.slice(0, k+1)` を渡せば、
k 日目の夜に画面へ出ていた判断が厳密に再現される。GARCH の最尤推定も BOCPD の逐次更新も
カルマンのレジーム分類も、すべてこの切り出しの内側で行われる。

同じ理由で、アナログ予測側の `predictSeries`（`weekly-analog-oos.ts`）も点時点整合である。
米国ビンの境界は `alignUsBins` が **切り出した価格の日付に整合する米国リターンだけ** から
分位を取るので、`us` に全期間の配列を渡していても未来の分位は混ざらない（確認済み）。

## 型ごとの採点則

| 判断の型 | 採点則 | ヌル／基準 |
|---|---|---|
| 方向 (up/down) | 的中率＋**Pesaran–Timmermann 検定** | 「常に多数派方向」。上げ相場では6割当たるので必須 |
| 確率 (上昇確率) | Brier＋**Murphy 分解**（較正誤差/分解能/不確実性） | 気候値 ō(1−ō)。BSS≤0 なら情報なし |
| 区間 (予測レンジ) | 被覆率＋**Christoffersen LR_uc**＋pinball 損失 | 名目水準（50/80/95%） |
| ボラ予測 | **Mincer–Zarnowitz 回帰**で (a,b)=(0,1) を Wald 同時検定＋QLIKE | a=0, b=1 |
| 連続量 (スコア類) | Spearman IC＋分位単調性 | CI が 0 をまたぐか |
| 警告 (変化点/ボラ急拡大) | 事象後の実現σの Welch t | 非発生時の実現σ |

重複窓（H日先を s 日ごとに評価すると ceil(H/s) 重）は
実効標本数 nEff = n/ceil(H/s) を併記し、CI はすべて移動ブロック・ブートストラップ。
MZ 回帰の標準誤差は Newey–West（Bartlett・ラグ=重複数−1）。

## 7203.T の実測（swing / 5営業日ごと / 直近5年・253点）

- **方向は全ホライズンで裏付けなし。** PT p = 0.10〜0.60 で、的中率(42〜53%)は多数派ヌル(60〜64%)を下回る。
- **確率も情報なし。** BSS は 1/5/21日すべて負（−0.016〜−0.079）。分解能は 0.002〜0.005 でほぼゼロ。
- **区間はおおむね較正されている。** 9本中7本が LR_uc で名目と整合。外れたのは1日50%(42.7%)と5日95%(90.5%)で、どちらも「狭すぎ」。
- **ボラ予測は情報はあるが水準がずれる。** 相関 0.24〜0.28 だが傾き b = 0.30〜0.89 と 1 を大きく下回り、Wald p<0.001。**そのまま使うと振れすぎる**（縮めて使う）。
- **変化点検知は5年間で発火0件。** この時間軸では事実上「常に無警告」で、警告として機能していない。閾値 `CHANGEPOINT_PROB=0.3`（`signal-digest.ts`）が厳しすぎる可能性がある。ただし当てに行って閾値を緩めれば偽警報が増えるだけなので、**採点結果を良く見せる方向の調整はしない**。

方向は当たらないがボラ・区間は較正されている、という非対称は理論通り
（系C26 個別ドリフトの識別限界・SPA検定 p=0.334 とも整合）。

## これは前向き検証ではない

as-of の切り出しが厳密でも、**「どの判断を採点するか」「どの閾値を使うか」を決めているのは今日の自分**である。
消せるのは先読みだけで、探索バイアスは消せない。年単位で待つ前向き検証台帳
（`docs/prospective-ledger-server.md`）の代わりにはならず、
**待たずに標本を稼ぐ代わりに、選択の自由度を抱えたままの検証**という位置づけになる。

またスコアカード1枚で 40 件超の検定が同時に走る（方向4＋確率3＋区間9＋ボラ4＋IC24＋イベント6）。
5%有意は期待値で2件出るので、1つだけ光る結果は多重性を先に疑うこと
（グローバル多重検定台帳 `edge-test-registry` を併読）。
