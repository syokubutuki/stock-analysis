# 設計書 ─ 銘柄除外セレクタ（ρ による「値動きが違う」検出つき）

対象: `/portfolio` の分析ID `pf-sector-select`（`SectorFactorSelectChart.tsx`）。
系C29（`docs/sector-factor-selection.md`）の P1 に**手で銘柄を外す導線**を足す小さな層。

**この設計書だけで着手できるように書いてある。** 数値はすべて 2026-08-08 の実測。

---

## 0. なぜ要るのか

`sec-bank`（16本）には**セブン銀行 8410.T が「低 b の対照」として意図的に入っている**
（`app/lib/universes.ts:226` のコメント）。P1 の S=b/σ_ε ランキングでは最下位に落ちるので
採用5本には入らないが、次の3つには影響が残る:

1. **James-Stein 収縮の中心 b̄** ── 低 b の外れ値が b̄ を押し下げる
2. **等加重バスケット因子**（`factorSource="basket"` のとき）── 因子そのものが汚れる
3. **横断診断**（ρ̄・N_eff・μ̂ スプレッド）

現状これを外す唯一の手段は「貼り付け」モードで16本のティッカーを毎回打ち直すことで、
常用に耐えない。

### 0.1 「値動きが違う」は ρ で測る（実測済み）

各銘柄と**残り全行の等加重バスケット（leave-one-out）**との生リターン相関 ρ を取る。
`sec-bank` / 窓750日 / 2023-07-12〜2026-08-07 の実測:

| 銘柄 | ρ | b̂ | 純度 | S |
|---|---|---|---|---|
| **あおぞら銀行 8304.T** | **0.503** | 0.36 | 19% | 1.32 |
| **セブン銀行 8410.T** | **0.564** | 0.26 | 18% | 1.51 |
| 京都フィナンシャルG 5844.T | 0.775 | 0.59 | 21% | 2.63 |
| ゆうちょ銀行 7182.T | 0.839 | 0.68 | 28% | 3.84 |
| 北洋銀行 8524.T | 0.839 | 0.89 | 30% | 3.44 |
| （他11行） | 0.87〜0.92 | 0.63〜1.17 | 22〜42% | 3.65〜8.06 |
| 横浜FG 7186.T | 0.922 | 0.85 | 30% | 4.73 |

**ρ の分布の最大の断層は 0.564 → 0.775 の間**にある。恣意的な線引きではなくデータが2群に割れている。
窓2400日でも拡張30ユニバースでも最下位2行は同じ（順位95%CI: セブン 15–16 / 14–14 / 29–30）。

### 0.2 ρ と純度を混同しないこと

**純度が低い ≠ 値動きが違う。** 三井住友トラストG 8309.T は純度22%で低純度警告に引っかかるが
ρ=0.890 で他行としっかり一緒に動いており、S=4.69 で7位。低純度の理由は
「市場βが 1.13 と b=0.63 に対して高いから」であって、外すべき銘柄ではない。
**除外セレクタが使う指標は ρ であって純度ではない。** 純度は既存の列のまま触らない。

## 1. 実装すること

### 1.1 lib: `app/lib/sector-factor-select.ts`（追加のみ・既存の挙動を変えない）

```ts
/** 「値動きが違う」と判定する ρ の閾値。実測の断層（0.564 → 0.775）の中間に置く。 */
export const RHO_ODD_THRESHOLD = 0.75;

// SectorSelectParams に追加
excludeTickers: string[];   // 既定 []

// AssetFactorFit に追加
/** 残り全行の等加重バスケット（leave-one-out）との生リターン相関。低いほど「値動きが違う」。 */
rhoBasket: number;
```

`computeSectorSelect` / `computeSectorPremise` の**冒頭で `pricesByTicker` から
`excludeTickers` を落とす**。＝「そのユニバースに最初から居なかった」のと同じ扱いにする。
`buildPanel` は**絶対に書き直さない**（履歴カバレッジ95%と価格破損の網が入っている）。

ρ の計算は既存部品だけで足りる:

```ts
// computeSectorSelect の銘柄ループ内。corr() と leaveOneOut() は同ファイル内に既にある。
rhoBasket: corr(panel.ret[keptIdx[i]], leaveOneOut(panel, keptIdx[i]))
```

> **添字の罠**: 回帰が落ちた銘柄は `rows` に入らないので `rows` の添字と `panel` の添字がずれる。
> 必ず `keptIdx[i]` を経由すること（`sector-factor-select.ts:1003` の既存コメントと同じ罠）。

`DEFAULT_SELECT_PARAMS` に `excludeTickers: []` を足す。**既定が空なので、除外0件のときの
出力は現行と1ビットも変わらない**（＝docs に残した実測値がそのまま再現される）。

### 1.2 コンポーネント: `app/components/analysis/SectorFactorSelectChart.tsx`

#### (a) 状態と永続化

```ts
// ユニバースごとに別の除外セットを持つ（sec-bank と sec-bank-wide で共有しない）
const [excluded, setExcluded] = useState<Record<string, string[]>>({});
```

localStorage キーは既存の流儀（`CollapsibleAnalysis.tsx:24` の `sa:open:${id}`）に合わせて
**`sa:sector-exclude:v1`** の1キーに `Record<UniverseMode, string[]>` を JSON で入れる。
**銘柄非依存**（再検索しても除外設定が残る）。読み書きは `useEffect` で、SSR 中に
`localStorage` を触らないこと。

#### (b) 2回計算する

除外した銘柄は `result.assets` に出てこないので、**そのままだとチェックを外せない**。
これを避けるため、診断用の軽い計算をもう1本走らせる:

```ts
// ① 診断用: 全銘柄。ρ とフラグの表示だけに使う。順位ブートは不要なので nBoot:0 で軽くする
const diag = useMemo(
  () => (factorPrices && activeCount >= 3
    ? computeSectorSelect(activePrices, factorPrices, { factorSource, window: windowLen, shrink, topK, nBoot: 0 })
    : null),
  [factorPrices, activePrices, activeCount, factorSource, windowLen, shrink, topK]
);

// ② 採用: 除外後。既存の表・図・ウェイトはすべてこちらを使う（＝現行の result のまま）
const keptPrices = useMemo(() => { /* activePrices から excluded[uniMode] を落とす */ }, [...]);
```

`nBoot:0` にすると `computeSectorSelect` 内の順位ブート（300反復 × N銘柄）が丸ごと飛ぶので
診断側は数十 ms で終わる。`nBootDone===0` のとき `rankLo/rankHi` は既定値になるが、
**診断側の順位CI は表示しない**ので問題ない。

#### (c) UI

ユニバースセレクタ（`uniMode` の `<select>`, 455行目付近）の直下に、
折りたたみの「銘柄の除外」パネルを置く。

```
▼ 銘柄の除外  [2/16 除外中]                      [推奨を適用] [全解除]
┌──────────────────────────────────────────────────────────┐
│ ☑ 8306.T 三菱UFJ FG        ρ=0.90  b=0.93  純度34%          │
│ ☑ 8411.T みずほFG          ρ=0.91  b=0.98  純度31%          │
│ …                                                          │
│ ☐ 8410.T セブン銀行        ρ=0.56  b=0.26  純度18%  ← 値動きが違う │
│ ☐ 8304.T あおぞら銀行      ρ=0.50  b=0.36  純度19%  ← 値動きが違う │
└──────────────────────────────────────────────────────────┘
```

- チェック **ON = 採用**（外すときにチェックを外す）。逆にしない ─ 「除外リスト」に見えると
  既定が全チェックOFF に見えて誤操作する。
- `ρ < RHO_ODD_THRESHOLD` の行に赤バッジ「値動きが違う」。
- **「推奨を適用」= フラグ付きを全部 OFF にする**だけ。自動では絶対に外さない
  （既定は除外0件。ユーザーが明示的に押したときだけ動く）。
- 既存の順位表（622行目付近の `<table>`）に **ρ 列**を1つ足す。
  `PurityBar` と同じ流儀の細いバーでよいが、**純度の色分けを流用しないこと**
  （閾値が別物なので同じ色にすると読者が混同する）。
- 除外中は表の直前にチップ行を出す: `除外中: セブン銀行 ×  あおぞら銀行 ×`（× で個別解除）。

#### (d) 開示（このリポジトリの規約）

除外すると **James-Stein 収縮率が上がる**（実測: 16本 4.6% → 14本 11.1% → 13本 13.5%）。
低 b の外れ値を抜くと b の横断スプレッドが縮み、**残った銘柄どうしの順位の識別力は落ちる**。
これは除外の副作用として正しい挙動だが、黙っていると「除外したら順位が信用できなくなった」と
読者が驚くので、除外が1件以上のとき注記を1行出す:

> 除外により b の横断スプレッドが縮み、収縮率が 4.6% → 11.1% に上がった。
> バスケットの目的には合うが、**残った銘柄どうしの順位の識別力は下がっている**。

## 2. 判断が要る点（Codex が勝手に決めないこと）

| # | 論点 | 既定 | 迷ったら |
|---|---|---|---|
| 1 | ρ の閾値 | **0.75**（実測の断層 0.564→0.775 の中間） | 定数 `RHO_ODD_THRESHOLD` を1か所に置く。UI スライダーにはしない |
| 2 | ρ を生存集合で再計算するか | **する**（＝実際に持つバスケットとの相関が知りたい量） | 下の §3 で暴走しないことを実測済み |
| 3 | 除外を universes.ts に反映するか | **しない** | `SEC_BANK` は書き換え禁止。過去の実測値（c=1.27 / b=0.97 / π=0.97）が再現できなくなる |
| 4 | 既定で除外を入れておくか | **入れない（0件）** | 既定を変えると docs の実測値と食い違う |
| 5 | watchlist モードでも使えるか | **使える**（`activePrices` を絞るだけ） | 保有銘柄を外しても保有そのものは消えない、と注記 |

## 3. 受け入れ基準（すべて実測で確認済み。同じ数字が出ること）

`sec-bank` / 窓750日 / factorSource=etf / topK=5 / 2026-08-08 時点:

1. **ρ の実測値**: あおぞら 8304.T = **0.503**、セブン 8410.T = **0.564**、
   京都FG 5844.T = **0.775**、他13行は **0.83〜0.92**。フラグが立つのは下2行だけ。
2. **除外0件のとき現行と完全一致**: 採用5本が
   三菱UFJ 31.1% / みずほ 21.8% / 三井住友 23.0% / りそな 12.4% / 千葉銀 11.7%、収縮率 4.6%。
3. **8410.T + 8304.T を除外すると N=14**、採用5本の**顔ぶれは不変**、ウェイトは
   31.1 / 21.8 / **23.1** / **12.2** / 11.7%（変化 ≤0.2pp）、収縮率 **11.1%**。
4. **ρ の再計算は暴走しない**: 2本除外したときの他14行の ρ の変化は**最大 0.0069**、
   除外後の最小 ρ は **0.776** で、閾値 0.75 を新たに割る行は出ない。
   （＝「外す→他が引っかかる→また外す」の連鎖は起きない）
5. 除外して残り3本未満になったら `computeSectorSelect` が `null` を返すので、
   **UI が落ちずに「銘柄が足りない」と出る**こと。
6. リロードしても除外が保たれる。ユニバースを切り替えると別の除外セットになる。
7. `npx tsc --noEmit` と `npx eslint <触ったファイル>` がクリーン。
   **`app/portfolio/page.tsx` の既存 lint エラー2件は本件と無関係（触らない）。**

## 4. 落とし穴

1. **`buildPanel` を書き直さない。** 履歴カバレッジ95%と価格破損の網が入っている。
2. **除外は共通日付の積集合を変える。** 履歴の短い銘柄を外すと窓が広がることがある
   （実測では 8410/8304 とも履歴が長いので窓は 2023-07-12〜2026-08-07 のまま動かなかった）。
   窓が動いたら日付表示も動くので、それは正しい挙動として受け入れる。
3. **`keptIdx` を経由せず `rows` の添字で `panel.ret` を引かない**（§1.1 の罠）。
4. **純度の色分けを ρ に流用しない**（§1.2c）。
5. **価格は必ず `/api/stock` 経由**。因子3本は `useBenchmarkPrices` のまま触らない（CLAUDE.md）。
6. **`DataQualityNotice` を消さない。** 1306.T は P0 で実際に価格破損を踏んでいる。
7. 除外セットに、そのユニバースに存在しないティッカーが残ることがある
   （ユニバース定義が更新されたとき）。表示時に交差を取って無視すること。

## 5. AnalysisGuide への追記（CLAUDE.md の規約）

既存の `<AnalysisGuide>` に**節を1つ足すだけ**でよい（7項目を書き直す必要はない）。含める内容:

- **ρ の定義**: `ρ_i = corr(r_i, (N·r̄ − r_i)/(N−1))` ── 自分を除いた等加重バスケットとの相関。
  自分を含むバスケットと相関を取ると恒等的に上振れするので leave-one-out にする。
- **なぜ純度ではなく ρ か**: 純度が低い銘柄には2種類ある。
  「市場に連動しすぎ」（三井住友トラスト: ρ=0.89・純度22%）と
  「そもそも別の商売」（セブン銀行: ρ=0.56・純度18%）。**外すべきは後者だけ**。
- **読み方**: 「ρ が 0.75 を割る銘柄は、金利ではない何かで動いている。
  セブン銀行は ATM 手数料、あおぞら銀行は…と、業態が銀行の金利ビジネスから離れているほど低い」
  （業態の理由は**推測なので断定しない**。データが示すのは相関だけ）。
- **注意点**: 除外は収縮率を上げる（§1.2d）。また**除外しても純度は上がらない** ──
  採用5本の加重市場βは 1.29 のままで、市場露出は銘柄選別では減らない（それは
  `docs/sector-market-hedge.md` の ★1 市場ヘッジの領域）。
