### 1. まず状態を把握する

```
git worktree list          # main と ..\sa-s25 の2本になっているはず
git branch -a
git status --short         # 親リポジトリが clean か（§0.8③ の事故）
git stash list             # 空か
git log --oneline main..feat/unit-thresholds
git diff --stat main...feat/unit-thresholds
```

**`git merge-base main feat/unit-thresholds` が main の HEAD と一致するか確認すること。**
一致しなければ、分岐後に main が触った概念を作業ブランチ側でも grep する（§0.5①）。
**第7波では、レビューが目視待ちで止まっている間に main が1コミット進んだ**（§0.11・学び⑦）。
**待ちが発生したら、再開時に `git log <分岐点>..main` を引き直すこと。**

### 5. 今回の固有リスク（★ S25 用。波が変わったらここを書き換える）

**S25 の失敗は「`dist-shape` の1件だけ直して、同じ形の他の箇所を数えていない」形か、
「非水準モードの累積リターン・DD を直したつもりで、`close` の値まで変えた」形で出る。**
第7〜第9波と同じく、**コードを数えるだけでは検算できない。**

**① FU59 — 分母が「比較相手の単位」で数えられているか（★ここが最重要）**

S24 の網は「表示値の単位」だけを数えたので、「割合を数えた条件が系列の単位を持つ」形を落とした（§0.13・学び①）。

- 棚卸しが lib の比較（`> 0.01`・`< -0.02` 等の定数）から**表示ラベルまで遡った表**になっているか。
  **`dist-shape` の1件だけ**なら、68パネルの lib を本当に見たかを疑うこと
- 直し方（σ単位・円のしきい値・欄を出さない）の選択と理由が書かれているか。
  lib の戻り値の形を変えたなら、**呼び出し元すべて**が棚卸しの表に載っているか
- `7203.T` と `0331418A` の `dist-shape` を **`mode=diff` で**本番ビルドで開き、
  **`>1%` と `>2%` に相当する2値が同じ値でない**（または欄が理由つきで消えている）こと。
  S24 の時点ではそれぞれ 49.51% / 49.51%、57.49% / 57.49% だった
- **`mode=close` / `mode=logReturn` のテール超過率が変わっていないか**も並べて見ること

**② FU61 — `close` の値を変えずに、非水準モードの異常値だけを消したか**

- (a) 出さない／(b) 比率から作り直す のどちらを選び、理由が書かれているか
- `mode=logReturn` / `diff` の `sa-transform` に **−100% を下回る DD・`NaN%` が無い**か
  （S24 時点: `7203.T` の logReturn で累積 −446.10%・最大DD −117.68%、`0331418A` で `NaN%`）
- **`close` の3値が分岐点と一致するか**（S24 時点の `7203.T`・10y: 累積 120.49% / 最大DD −41.67% / 現在DD −25.24%。
  配信値が動くので、平日は応答を固定し、休場日なら2つのビルドを同時に起動して並べること → §0.13・学び②）
- 棚卸しが `sa-transform` 以外にも「水準用の式に非水準が流れる」箇所を探しているか

**③ FU60 / FU62 / FU57 — 小さい3件が本当に片付いているか**

- `VolatilityChart` の色分けが、`diff` のとき円の値と `%` 前提の定数を比べていないか
- `series-mode.ts` の差分が**コメントと関数の追加だけ**か（既存関数の挙動を変えていたら専有の線を越えている）
- `app/lib/event-markers.ts` が消え、**文字列参照も0件**か（`/axioms` のように部品名を文字列で持つ場所がある → §0.12・学び③）

**④ 「それ以外」欄が空でないか**

第7波（E1/E2 → FU51）・第8波（`vol-cone` の lib）・第9波（`sa-transform` の DD → FU61）とも、
一番大きいものは「それ以外」欄か、その手前の除外判断から出た。
**空の「それ以外」欄が返ってきたら、全節を開いていない証拠として疑うこと**（§0.11・学び⑤）。

**⑤ 前後比較の分岐点ビルド**

分岐点を別の作業ツリーに展開して `node_modules` をジャンクションで共有すると、Turbopack の `next build` が落ちる。
**分岐点だけ `next build --webpack` でよい**（§0.13・学び④）。作業ブランチ側は `npm ci` して通常ビルドすること。

**⑥ S21〜S24 が固定した黄金値が落ちていないか**

**⑧ lint の警告が、行単位の diff で説明できるか（★受け入れ条件7。総数の一致ではない）**

着手前の値を**自分で測ること**。分岐点と作業ブランチで `npx eslint . -f json` を流し、
**ファイル・ルール・メッセージで1対1に突き合わせる**（S24 のレビューでは「同じ行／行番号だけ移動／消えた／新たに出た」の4区分に分けた → §0.13④）。
ESLint 9 には `-f unix` が無いので JSON で出すこと。
FU57 で `event-markers.ts` を消すと、そのファイルに付いていた警告（あれば）はファイルごと消える。**それ以外の差**があれば指摘すること。

**⑨ 秒や外部取得の主張があれば、自分で測り直すこと。ただし回線差を織り込むこと**

第7波では実装側 5.81秒 / レビュー側 9.27秒で、**絶対値は再現しなかった**（回線差）。
**構造（往復回数・HIT の速さ）が再現するかで見ること。** 今回は秒の主張は出ないはずである。

**⑩ ブラウザでの走査**

Claude の内蔵ブラウザ（pane）があれば、それで `localhost` の本番ビルドを開けば足りる（S24 のレビュー → §0.13⑥）。
無ければ **headless Edge を CDP で操作する**（memory `headless-edge-cdp-fallback`。S23 はこの経路）。
どちらでも、`localStorage` の `sa:open:<id>` を 1 にしてから節ごとに読み込み直し、
**「読み込み中」の残数が 0 であることを確認してから**走査すること。
**ポートが違えば origin も違い、`localStorage` も別になる**ので、分岐点側と作業側の両方で立てること。

**ただし人の目ではない。** 報告には「人の目ではない・スクリーンショットの有無・狭い画面は未確認」を書くこと。
