**① `0331418A` と `7203.T` の両方を、自分で本番ビルドで開いたか（★ここが最重要）**

`npm start` の本番ビルドで、少なくとも次を見ること。**dev では見ないこと。**

```
# 投信（本命）
0331418A → 基本節（ローソク足の凡例）・分布節（平均/標準偏差の書式）・全節を開く
# 株式（退行の対照）
7203.T   → 同じ2節。凡例が消えていないか・書式が変わっていないか
```

**「投信で直った」だけでは足りない。株式で退行していないことが受け入れ条件5である。**
S18 の A3 は「実装したか」ではなく「聞いたか」でしか検算できなかった（§0.9・学び①）。
今回も同じで、**「直したか」ではなく「見たか」でしか検算できない。**

**② 棚卸しの「それ以外」欄が埋まっているか（★受け入れ条件1）**

プロンプトは「3つのFUに入らないものを必ず作れ」と書いてある。
**空だったら、それは全節を開いていない証拠である可能性が高い。**
§0.9④ のとおり、投信の分布節を全開した時点で FU47 が見つかった。
**全節を開けば、3件では収まらないはずである。**

**③ FU47 — 分母が出ているか。そして「全部直した」と言っていないか**

`%` を付けている箇所のうち水準が流れうるものの**件数**が出ていること。
S18 は Canvas 150件中10件を直して条件を満たしたように見えた（§0.7①）。
**今回は逆に「全部直した」と書いてあるほうを疑うこと。**
`%` の付与箇所は全アプリで数百あり、1セッションで全件を判断するのは現実的でない。
**「ここまで直し、ここは残した」と書いてあるのが正常である。**

`series-mode.ts` を触ったなら:

```
git diff main..HEAD -- app/lib/series-mode.ts app/lib/__tests__/series-mode.test.ts
```

**AGENTS.md が名指しする回帰テスト対象**である。黄金値を録り直しているなら、
**「実装とテストのどちらが正しいか」の判断が報告に書かれていること。**

**④ FU32 — 描画方式を変えていないか**

(b)「投信ではローソク足で描かず終値の線にする」を選んだ場合、**描画方式の変更**である。
CLAUDE.md のチャート規約（時間軸は `lightweight-charts`）は守られているか。

```
git diff main..HEAD --stat -- app/components/analysis/
grep -c 'createChart(' -r app/components/ ; grep -c 'getContext("2d")' -r app/components/
```

第3波・第5波では `createChart(` **142** / `getContext("2d")` **175（152ファイル）** で不変だった。
**増減があれば理由を確かめること。**

`TrendJudgment.tsx`（FU49・未配線）を「直した」ことになっていたら、
**画面に出ないものを直しているので指摘すること**（無害だが、件数を水増しする）。

**⑤ FU15 — 「速くしました」を疑う**

`/api/stock` を迂回する解になっていないか。**`repairPriceGlitches()` を通らない経路は
CLAUDE.md 最優先の違反**であり、差し戻し対象である。

```
git diff main..HEAD -- app/lib/stock-source.server.ts app/api/
grep -rn 'repairPriceGlitches' app/api/ app/lib/stock-data.server.ts

キャッシュで速く見えているだけの可能性もある。**初回（MISS）の秒を測ること。**

**⑥ S21 が固定した黄金値が落ちていないか**

### 6. 検証を走らせる

```
# worktree で
npm test        # 163件（マージ前の main での実測。増減を報告すること）
npm run lint    # 0エラー / 272警告（増減があれば報告）
npm run build

# マージ後の main でも、もう一度
npm test; npm run lint; npm run build
npm start       # ★ dev ではなく本番ビルドで、変更した画面を実際に開くこと
```

**テストが落ちたら、直す前に「実装とテストのどちらが正しいか」を報告すること。**
