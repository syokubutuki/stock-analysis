### 1. まず状態を把握する

```
git worktree list          # main と ..\sa-s23 の2本になっているはず
git branch -a
git status --short         # 親リポジトリが clean か（§0.8③ の事故）
git stash list             # 空か
git log --oneline main..feat/display-details
git diff --stat main...feat/display-details
```

**`git merge-base main feat/display-details` が main の HEAD と一致するか確認すること。**
一致しなければ、分岐後に main が触った概念を作業ブランチ側でも grep する（§0.5①）。
**第7波では、レビューが目視待ちで止まっている間に main が1コミット進んだ**（§0.11・学び⑦）。
**待ちが発生したら、再開時に `git log <分岐点>..main` を引き直すこと。**

### 2. 棚卸しコミットを読む

**棚卸しの数値を、自分で数え直すこと。** 報告された N を鵜呑みにしない。

### 5. 今回の固有リスク（★ S23 用。波が変わったらここを書き換える）

**S23 の失敗は「代替テキストを直したつもりで、可視テキストとずれた」形か、
「投信で見つけたものを投信だけで直して、株式に同じ欠陥が残った」形で出る。**
第7波と同じく、**コードを数えるだけでは検算できない。**

**① `0331418A` と `7203.T` の両方を、自分で本番ビルドで開いたか（★ここが最重要）**

`npm start` の本番ビルドで、少なくとも次を見ること。**dev では見ないこと。**

```
# 株式（FU51 はこちらでも出る。★ここを飛ばさない）
7203.T   → simulation 節（sim-optstop）・volatility 節（vol-cone）
# 投信
0331418A → 同じ2節 ＋ basic 節（FU53: 既定系列から出来高が外れたか）
```

**走査は `innerText`（可視）と配下の全 `[aria-label]`（代替）の両方を取ること。**
E2（`vol-cone`）は**可視側に無い数値**なので、可視だけ見ると見つからない（§0.11・学び⑤）。

**各節で「読み込み中」の残数が 0 であることを確認してから走査すること。**
「すべて開く」直後の読み取りは `next/dynamic` のチャンク待ちを掴んで
**「異常なし」という誤った結果を返す**（`docs/fund-display-inventory.md` §0）。

**② 代替テキストと可視テキストの値が一致するか（★受け入れ条件2）**

FU51 の本質は「同じ量が2箇所に出ていて、片方だけ100倍」である。
**直した後に両方を突き合わせること。** 片方だけ見ても「直った」と言える形なので、
**報告に両方の値が並んでいなければ検算できていない。**

**③ 分母が出ているか。そして「全部直した」と言っていないか**

FU51 は「lib が既に百分率にしているのにコンポーネントがもう一度100倍」の型である。
**2件（`sim-optstop` / `vol-cone`）で終わるとは限らない。**
FU45 で2件・S22 の棚卸しで2件出ているので、**同じ型を全件走査したかを見ること。**

**lib とコンポーネントのどちらを直したか**が書かれていること。
lib 側を直したなら、**その lib の他の呼び出し元が全部ずれていないか**を確かめること。

**④ FU53 — 株式で退行していないか**

投信で「出来高」が既定から外れたなら、**株式では外れていないこと**を実機で見る。
判定に `hasCloseOnlyMarketData`（出来高も条件に入れる）を使ったか、
`hasCandlestickBodies`（OHLC だけを見る）を使ったかで意味が変わる。
**FU53 は出来高の話なので前者が正しい。** 後者を使っていたら指摘すること。

**⑤ FU49 — 単品で消していないか**

一覧が先に出ていること。**`TrendJudgment.tsx` だけ消して終わっていたら不足である。**
残す判断をしたなら、**理由がファイル冒頭に書かれているか**（次の波が同じ調査をしないため）。

**⑥ S22 が固定した黄金値が落ちていないか**

```
npm test
# series-mode（SERIES_MODE_UNITS の網羅・extractRatioSeries の素通し・水準が%に流れない）
# chart-colors（hasCandlestickBodies が両方向で正しい）
# tiers（無料86/有料166）・ticker-pages（99/1/98）・og-font-charset（cmap 一致）
```

パネルを増減していないので**落ちないはずである。落ちていたら何かを壊している。**

**`app/lib/series-mode.ts` と `app/lib/chart-colors.ts` は今回「触らないこと」に入っている。**
差分が出ていたら、**FU50 / FU52 に手を出していないか**確認すること（担当外）。

**⑦ パネルIDが1つも変わっていないか（★受け入れ条件6）**

```
diff <(git show main:app/lib/panel-registry.tsx | grep -o 'id: "[^"]*"' | sort) \
     <(git show feat/display-details:app/lib/panel-registry.tsx | grep -o 'id: "[^"]*"' | sort)
```

差分が出たら**共有URL `?panel=` と `sa:open:<id>` が壊れる**（§6.5）。

**⑧ lint の警告数が着手前と同じか**

着手前の値を**自分で測ること**（分岐点で `npm run lint` を流し、出力を行単位で比較する）。
第5〜第7波では総数だけでなく**ルール構成とファイル集合まで一致**することを確認した。
同じ強さで見ること。

**⑨ 秒や外部取得の主張があれば、自分で測り直すこと。ただし回線差を織り込むこと**

第7波では実装側 5.81秒 / レビュー側 9.27秒で、**絶対値は再現しなかった**（回線差）。
**構造（往復回数・HIT の速さ）が再現するかで見ること。**
絶対値の断定（「もう N 秒は出ない」）があれば、**回線に依存する主張だと指摘する。**

**⑩ ブラウザ拡張が繋がらないときの代替**

拡張が未接続なら `mcp__claude-in-chrome__list_connected_browsers` が空になる。
そのときは**「本番ビルドを起動し、実データで新旧のコードパスを Node で再現する」**を先に行い、
**棚卸しが報告した数値が再現するか**で忠実さを検算する（§0.11・学び②）。

**ただしこれは目視の代わりにならない。**「出ていないこと」の確認
（凡例が消えた／既定系列から外れた）は画面でしか言えない。
**代替で済ませたなら、済ませたことを報告に書くこと。**
