### ラウンド4で新たに分かったこと — 次のラウンドの判断が変わる

> **①②③ は 2026-08-17 に対処済み**（コミット `cf09c48` / `7126c26` / `6378813`）。
> 以下は「何が起きていたか」の記録として残す。**現在の状態は各項の末尾を読むこと。**

**① `/t/[ticker]` は SSG されていない**

`export const dynamic = "force-dynamic"` のため、ビルド出力は `ƒ (Dynamic)` である。
R1 の受け入れ条件5「ビルド時間の実測値を報告する」は**満たす対象が消えた**（ビルド時間への影響ゼロ）。

さらに調べて、遅さの本体が別にあることが分かった。
**銘柄ページだけが `getStockData(symbol, "1y")` を呼んでいた。**
アプリ本体・`/api/stock`・全ベンチマーク取得は例外なく `range=10y` で、
`cacheKey()` は range を含む（`stock-data.server.ts:51`）。
つまり **`1y` は誰も温めない専用エントリ**で、常に MISS を踏みやすい構造だった。

**もう一つ、CDN では解決しない。** Vercel は検証済みSEOクローラに対して
CDN キャッシュを **BYPASS** する（`cacheReason: crawler`）。
クローラの初回応答を支えられるのは Runtime Cache か ISR だけである。

**対処（`cf09c48` / `7126c26`）**:
- 取得を `10y` に寄せ、掲載する直近1年は `buildTickerPageSummary()` が切り出す。
  **通常のアプリ利用が銘柄ページのキャッシュを温めるようになった**
- `next.config.ts` に `/t/:ticker` の `Vercel-CDN-Cache-Control`
  （`s-maxage=900, stale-while-revalidate=86400`）。**これはクローラには効かない**。
  効くのは人間の再訪・SNS展開・プレビュー取得
- ISR 化はしていない（`cache: "no-store"` が動的に倒すため、価格取得層に手を入れる話になる）。
  `generateStaticParams()` は将来の起点として残してある

→ **S14 への申し送り**: OG画像のキャッシュ設計を CDN 前提で組まないこと。
`s-maxage=900` は `/t/:ticker` の1セグメントにしか当たらないので、
`/t/:ticker/opengraph-image` は自分で方針を決めること。

**② `/t/7203.T` は 404 になる（リダイレクトしない）**

`dynamicParams = false` は、`generateStaticParams()` に無い params を
**ページ本体の実行前に** 404 にする。そのため `page.tsx` に書かれた
Yahoo記法 → canonical の `permanentRedirect` は**一度も実行されない死んだコード**である。

**対処（`cf09c48`）**: `dynamicParams = true` に戻した。実測で
`/t/7203.T` → **308 → `/t/7203`**、`/t/7203.t` も同じ。未知のコードは
`getTickerPageInstrument()` → `notFound()` が受けるので防御は変わらない。

補足: `/t/aapl` は 308 にならず 404 のままだが、これは正しい。
**AAPL は公開対象ではない**（`TICKER_PAGE_INSTRUMENTS` は `major100` 由来＝国内株のみ）。
大文字化の正規化そのものは `7203.t` で効いていることを確認した。

**③ 非対応パネルの台帳は fail-open である**

FU17 の 74＋24 = 98 IDは `app/page.tsx` にハードコードされている。
**新しいパネルを追加して台帳に載せ忘れると、投信で無意味な結果がそのまま出る。**
壊れる方向ではないので気づきにくい。

**対処（`6378813`）**: 台帳を `app/lib/panel-data-requirements.ts` へ出し、
3つ目の `CLOSE_ONLY_SAFE_PANEL_IDS`（153件）を置いた。
`page-wiring.test.ts` が **`page.tsx` の全251IDがちょうど1分類に属すること**を検査するので、
分類を忘れたパネルは `npm test` が落とす。逆向き（改名で台帳が腐る）も同時に検査する。

**残る2つの穴（テストでは埋まらない）**:
- `SAFE` は**検証済みという意味ではない**。移設時点の挙動を写しただけである。
  実際、高値・安値を必要とするのに SAFE に入っているものが4件見つかった
  （`tech-adx` / `tech-breakout` / `vol-atr` / `tech-stoch`）。
  挙動を変えないため今回は SAFE のまま残し、理由をファイル冒頭に記録した → **FU26**
- `discretionary`（裁量トレード）節は `AccordionSection` を使わず
  `DiscretionaryLab` を直接描くため、**パネルIDを持たずこの仕組みの外にある** → **FU27**

ラウンド3の brotli 実測（実転送 47.5 KB）を根拠に、親文書 §11 の状態を

### 第1波で新たに分かったこと — 次のセッションの判断が変わる

**① 両ブランチとも 2026-08-17 の3コミットより前の main から分岐していた**

**`opengraph-image.tsx` が `getStockData(symbol, "1y")` のまま残っていた。**

`cf09c48` が銘柄ページを `10y` へ寄せたのは、`cacheKey()` が range を含むため

> 無衝突マージを「整合が取れている」と読まないこと。次の S15 / S17-S19 では

**② `next/og` のフォント同梱は base64 埋め込みが正解だった**

Next のドキュメントにある `fetch(new URL("./x.ttf", import.meta.url))` は

`fs.readFile` はファイルトレーシング頼みで、落ちたときに**画像だけが静かに退化する**。
`_fonts/subset-base64.ts` に base64 で埋め込む形はどちらにも依存しない。
**S18 で画像を扱うなら同じ手を使うこと。**

**③ 「数えた対象がそもそも不完全」という失敗の形が再発した**

FU12 は `#9ca3af` / `#94a3b8` の2値で386箇所と数えていたが、同じ Canvas 内に

> **教訓: 受け入れ条件に「N箇所」と書いたら、そのNの数え方自体を疑うこと。**
> 「grep の網に入らない表記が別にないか」を各セッションの最初に確認させること。

## 2. worktree の準備

> ### ⚠ シェルを間違えないこと
> **この環境の既定ターミナルは PowerShell である。** bash 版を PowerShell に貼ると
> `$dir` / `$br` が展開されず、リポジトリ内部に不正な worktree が作られる（2026-08-11 に発生）。
> 誤作成したら: `git worktree remove '$dir' --force; git worktree prune; git branch -D '$br'`

### PowerShell 版（この環境の既定シェル）

```powershell

if (git status --porcelain) {
  Write-Host "中断: 未コミットの変更があります。worktree から見えないので先にコミットしてください。"
  git status --short
} else {
  # ★ 第1波（S14/S16）は完了・削除済み。次に作るのはここ:
  #   第2波: @{ Dir = '..\sa-s15'; Branch = 'feat/panel-badge' }   ← 単独
  #   第3波: @{ Dir = '..\sa-s17'; Branch = 'feat/panel-followups' }
  #          @{ Dir = '..\sa-s18'; Branch = 'feat/canvas-alt-text' }
  #   最後 : @{ Dir = '..\sa-s19'; Branch = 'feat/panel-registry' }  ← 単独
  $pairs = @(
    @{ Dir = '..\sa-s15'; Branch = 'feat/panel-badge' }
  )
  foreach ($p in $pairs) {
    git worktree add $p.Dir -b $p.Branch
    if ($?) { Push-Location $p.Dir; npm install; Pop-Location }
  }

  Write-Host "`n完了。参照文書の存在を確認します:"
  $docs = @(
    'AGENTS.md', 'CLAUDE.md', 'NEXT_SESSION.md',
    'docs/site-improvement-execution-plan.md',
    'docs/site-improvement-round4.md', 'docs/site-improvement-round5.md'
  )
  foreach ($p in $pairs) {
    $n = ($docs | Where-Object { Test-Path (Join-Path $p.Dir $_) }).Count
    "  {0} : 6文書中 {1} 個" -f $p.Dir, $n
```

**6/6 にならなければ投入しないこと。**

### ⚠ 分岐点を古くしないこと（§0.5① の教訓）

`git worktree add -b` は**その時点の HEAD から切る。** 第1波は worktree を作った後に
main へ3コミット入り、**無衝突マージなのに意味が壊れた**（OG画像だけが `range=1y` に
取り残された）。したがって:

1. **worktree はセッションを投げる直前に作ること。** 先に作り置きしない
2. セッションが数日にまたがったら、**作業ブランチで `git merge main` を実行させること**
3. マージ後は「無衝突だった」で終わらせず、
   **`main` 側の変更が触った概念を作業ブランチ側でも grep すること**
   （今回なら `getStockData(` の range 引数）
