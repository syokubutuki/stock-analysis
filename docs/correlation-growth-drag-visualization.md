# 「相関を無視してリターンを追う」＝長期成長率を削る操作 — 可視化提案

対象: 投資初心者。目標は「読めば分かる」ではなく **「見た瞬間に分かる」**。
既存の `pf-entry-sizing⑤`（成長率カーブ g(λ)/g_max = 2λ−λ²）は数式として正しいが、λ という抽象量が入口に立っているため初心者には届かない。本提案はその手前に**直感の層**を敷く。

---

## 0. 結論（1画面に載せるべき3つ）

| # | 見せるもの | 一言 |
|---|---|---|
| ① | **ウォーターフォール分解** `μ → −単独ドラッグ → −相関ドラッグ → g` | 「相関が食べた分」が赤い1本の棒として見える |
| ② | **三本の崖**（ρ=0 / 0.5 / 0.8 の g(建玉%) 放物線＋現在地ドット） | 入口の傾きは同じ。崖の位置だけが違う |
| ③ | **隠れレバレッジ倍率** `√(N/N_eff)` の特大数字 | 「10銘柄に分散したつもり → 実質1.8銘柄を **2.4倍のレバレッジ** で持っている」 |

この3つが同じスクロール位置に並び、**ρスライダー1本で全部が同時に動く**のが理想形。

## 1. 核となる分解（これが全ての可視化の背骨）

等ウェイト N 銘柄、各銘柄のボラ σ、平均相関 ρ、総建玉（現金含む資産に対する比率）W とする。

```
σ_p²  =  W²σ² · [ 1/N + (1−1/N)·ρ ]
       =  W²σ²/N_eff                     N_eff = N / (1 + (N−1)ρ)

g     =  W·μ  −  σ_p²/2
       =  W·μ  −  W²σ²/(2N)  −  W²σ²(1−1/N)ρ/2
          ~~~~     ~~~~~~~~~~     ~~~~~~~~~~~~~~~~
          期待     単独ドラッグ     相関ドラッグ
                  （避けられない）  （相関を無視した代償）
```

**この3項分解が本提案の全て。** 期待項は W に**比例**、ドラッグ項は W の**二乗**。だから建玉を増やすと期待は直線的に伸びるのに、成長率はどこかで必ず折り返す。そして ρ はその折り返し点を左に引き寄せる。

派生する2つの「効く数字」:

```
N / N_eff   = 1 + (N−1)ρ          … ドラッグが何倍に膨らんだか（＝ボラティリティ税の倍率）
√(N/N_eff)  = √(1 + (N−1)ρ)        … 隠れレバレッジ倍率（思っていたリスクの何倍か）
```

> **N/N_eff の意味を言い切る**: 「N/N_eff = 6.4」は抽象的な指標ではなく、
> **「あなたが払っているボラティリティ税は、本当に分散できていた場合の 6.4 倍」** という直接的な意味を持つ。
> ここを明示するだけで N_eff の危険度が伝わる。UIでは必ずこの文言をセットで出す。

現実的な数値（N=10）:

| ρ | N_eff（実質銘柄数） | N/N_eff（税の倍率） | √(N/N_eff)（隠れレバ） |
|---|---|---|---|
| 0.0 | 10.0 | 1.0× | 1.00× |
| 0.2 | 3.6 | 2.8× | 1.67× |
| 0.3 | 2.7 | 3.7× | 1.92× |
| **0.5**（日本株大型の実勢） | **1.8** | **5.5×** | **2.35×** |
| 0.7（同業種） | 1.4 | 7.3× | 2.70× |
| 0.9 | 1.1 | 9.1× | 3.02× |

**ρ=0.5 で既に「10銘柄 → 実質1.8銘柄」。** この1行が最も破壊力がある。

## 2. グラフ案

### G1. 三本の崖（★最優先・ヒーローチャート）
- 横軸 = **総建玉（資産に対する%、0〜300%）**。λ ではなく初心者が自分で把握できる量にする。
- 縦軸 = 年率の実質成長率 g。
- 曲線を3本: ρ=0（緑）／ρ=0.5（黄）／ρ=0.8（赤）。**原点での傾きは3本とも同一**（同じ μ）。
- g<0 の領域を薄赤で塗る。各曲線の頂点に「▲ここが最速」、g=0 交点に「資産が増えなくなる」ラベル。
- ユーザーの現在地を白丸で打つ。ρスライダーを動かすと**丸は動かないのに、足元の崖だけが左にずり寄ってくる**。

> 「自分は何も変えていないのに、相関が上がっただけで崖から落ちる」という体験が、この1枚で完結する。

μ=8%, 単独σ=30%, N=10 のとき:

| ρ | 最速となる建玉 | 成長率ゼロになる建玉 |
|---|---|---|
| 0.0 | 890% | 1780% |
| 0.5 | 162% | 324% |
| 0.8 | 108% | 216% |

ρ=0.8 では**信用2.2倍で成長率がゼロ**になる。フル現物（100%）ですら既に頂点の手前ぎりぎり。

### G2. ウォーターフォール（★最優先）
```
 +16.0% ┃████████████████  期待リターン（見かけ）
        ┃          ▼
  −1.1% ┃          ██      単独ドラッグ（分散しても残る分）
        ┃            ▼
  −8.9% ┃            ████████████  相関ドラッグ ← 相関を無視した代償
        ┃                     ▼
  +6.0% ┃████████            実際に増える速さ（幾何成長率）
```
- 一番長い赤棒が「相関ドラッグ」になるのが実データの通例。ここに **「相関が食べた分」** とだけ書く。
- 数式ゼロで因果が伝わる。棒の長さがそのまま損失額（円）でも併記できる（例: 投下資金300万に対し年▲26.7万）。

### G3. 双子メーター（期待↑／実際↓ の同時逆行）
- 上下2本の横棒。上＝算術平均（青、右に伸びる）、下＝幾何成長率（緑、縮む）。
- 銘柄を1つ足すボタン／ρスライダーを動かすと、**上が伸びながら下が縮むアニメーション**。
- 2本の差分を赤い帯で埋め「ドラッグ」と表示。差が開いていく様子そのものがメッセージ。

### G4. 終端資産のヒストグラム（対数軸）
- モンテカルロの最終資産分布。**平均（算術）と中央値（幾何）に別々の縦線**を立てる。
- 平均線は右の裾に立ち、その右側の面積が「平均以上になった人の割合」= 例えば 21%。
- キャプション: **「"期待リターン" に届く人は5人に1人。残りの8割は中央値の世界に住む」**
- ρを上げると分布が横に潰れて長く伸び、平均線と中央値線の距離が開く。

### G5. リスクの二つの顔（円グラフ2枚並置）
- 左: 資産配分の円グラフ（きれいに10等分）→「見た目の分散」
- 右: **リスク寄与率 PCTR** の円グラフ（1〜2銘柄で6割）→「本当の分散」
- さらに右に3枚目として**主成分の寄与率**（PC1 が 78% など）→「あなたのポートフォリオは実質1つの賭け」
- 既存 `portfolio-risk.ts` の PCTR をそのまま流用できる。実装コスト最小で効果大。

### G6. 幾何フロンティア（既存 `pf-frontier` への追加）
- 既存の効率的フロンティア（μ–σ 平面）に **g = μ − σ²/2 の等高線（iso-growth 曲線）** を薄く重ねる。
- 等高線は上に凸の放物線群。フロンティアが右上に伸びても等高線を**下向きに横切る**ので、「フロンティアの右上端＝最も儲かる点」ではないことが図で分かる。
- 接点ポートフォリオ（最大Sharpe）と**最大成長点**が別の場所にあることをマーカーで示す。追加実装は等高線描画のみ。

## 3. 表案

### T1. 「1銘柄ずつ足していく台帳」（★実データ・最も説得力がある）
ウォッチリストを**既存ポートフォリオとの相関が高い順**に並べ、上から1つずつ組み入れていく。初心者が実際にやる「似た銘柄をどんどん買う」を再現する。

| 追加 | 既存との相関 | 期待リターン | σ_p | ドラッグ | **実質成長率 g** | N_eff | 隠れレバ |
|---|---|---|---|---|---|---|---|
| 1銘柄目 | — | 8.0% | 30.0% | 4.5% | **3.5%** | 1.0 | 1.00× |
| +2銘柄目 | 0.72 | 16.0% ↑ | 55.7% | 15.5% | **0.5%** ↓ | 1.16 | 1.31× |
| +3銘柄目 | 0.68 | 24.0% ↑ | 80.5% | 32.4% | **−8.4%** ↓ | 1.24 | 1.55× |

- **期待リターンの列は緑↑で伸び続け、g の列は赤↓で沈む。** 同じ行の中で矢印が逆を向く。
- g が減少に転じた行をハイライトし **「ここから先は、足すほど遅くなる」** と注記。
- 「1銘柄あたり同じ金額を張り続ける（＝現金を減らす／信用を使う）」前提であることを表の上に明記する。これが「分散したつもりがレバレッジ」の正体。

### T2. ±x% 往復表（数式ゼロで幾何平均を理解させる）

| 値動き | 算術平均 | 2回後の資産 | 実質 |
|---|---|---|---|
| +10% / −10% | 0% | 99.0万 | **−1.0%** |
| +20% / −20% | 0% | 96.0万 | **−4.0%** |
| +30% / −30% | 0% | 91.0万 | **−9.0%** |
| +50% / −50% | 0% | 75.0万 | **−25.0%** |

「**平均は全部ゼロなのに、振れ幅が大きいほど減る**」。減り方が振れ幅の**二乗**（x²/2）で効いている、が σ²/2 の正体。

### T3. 分割 vs 追加（2つの操作を分ける表）
初心者の混同を正面から解体する。

| | A: 分割（100万を N 分割） | B: 追加（各銘柄に100万ずつ） |
|---|---|---|
| 総建玉 | 100%（不変） | N×100% |
| 期待リターン | 変わらない | N倍 |
| σ_p | **下がる**（ρ<1 なら必ず） | 上がる |
| 幾何成長率 | **必ず改善** | ρ次第で悪化 |
| 正体 | 本物の分散 | **レバレッジ** |

**「分散投資したつもりが、実際はレバレッジを掛けていただけ」= B を A だと思っている状態。** 表を2列並べるだけで一発で伝わる。

## 6. 数式を使わない説明（そのままUIに載せる文言案）

> **なぜ「期待リターン」は嘘をつくのか**
>
> 「期待リターン」は足し算の世界の言葉です。100人が1回ずつ賭けたときの、100人の平均。
> でもあなたの資産は掛け算で増えます。今年の結果に来年の結果を**掛ける**。
> 掛け算の世界では、上下に揺れること自体が資産を削ります。+10%と−10%を繰り返すと、
> 平均は0%なのに資産は減っていく。この「揺れの分の目減り」を **ボラティリティ税** と呼びます。
>
> 銘柄を足すと期待リターンは足し算で増えます。でも税は**二乗**で増えます。
> しかも、似た値動きの銘柄を足すと揺れは打ち消し合わず、そのまま積み上がる。
> だから「良さそうな銘柄を見つけるたびに買い足す」は、期待リターンを増やしながら、
> それ以上の速さで税を増やす操作になります。
>
> **10銘柄持っていても、値動きがそっくりなら、それは1銘柄を10倍の大きさで持っているのと同じです。**

## 7. 数式を使う説明（AnalysisGuide 用・省略なし）

**定義**
- 対数リターン `r_t = log(P_t / P_{t−1})`、資産の成長は `W_T = W_0 · exp(Σ r_t)`。
- 算術平均（期待リターン）`μ_a = E[単純リターン]`、幾何平均（実質成長率）`g = E[log(1+単純リターン)]`。

**両者の関係（2次までの近似）**
```
g ≈ μ_a − σ²/2
```
（導出: `log(1+x) ≈ x − x²/2` を期待値に取り、`E[x²] ≈ σ²` とする。対数正規なら**近似ではなく厳密**。）
`σ²/2` が**ボラティリティ・ドラッグ**。

**ポートフォリオの分散**
```
σ_p² = Σ_i Σ_j w_i w_j σ_i σ_j ρ_ij
```
等ウェイト・共通 σ・共通 ρ の場合:
```
σ_p² = σ² [ 1/N + (1−1/N)ρ ] = σ² / N_eff ,   N_eff = N / (1 + (N−1)ρ)
```

**成長率の3項分解**（総建玉 W）
```
g(W) = W·μ − W²σ²/(2N) − W²σ²(1−1/N)ρ/2
```

**最適建玉とフルケリー比**
```
W* = μ / σ_single²  （σ_single = 単一ベット換算のボラ = σ/√N_eff）
λ  = W / W*
g(λ)/g_max = 2λ − λ²
```
λ=1 で最大、**λ=2 で成長率ちょうどゼロ、λ>2 で資産は減る**（期待値は増え続けているのに）。
既存 `weekly-allocation.ts` の `lambdaOf` / `growthRatio` がこれ。

**「相関を無視する」の数学的な意味**
`ρ` を 0 と誤認して W* を計算すると、真の最適の `√(1+(N−1)ρ)` 倍の建玉を持つ。すなわち
```
λ_true = √(N/N_eff) = √(1 + (N−1)ρ)
```
N=10, ρ=0.5 で λ=2.35 → `2λ−λ² = −0.82`。**成長率は最大値の −82%、つまり資産は減っていく。**
これが「相関を無視してリターンを追う」の定量的な代償である。

## 8. シミュレーション結果の見せ方

### S1. 2つの世界のレース（★）
同じ μ・同じ銘柄数・同じ総建玉で、`ρ=0` の世界と `ρ=0.7` の世界を**同じ乱数種**で走らせる。
- 薄い線で各300パス、太線で中央値パス、破線で平均パス。
- **平均パス（破線）は2つの世界でほぼ重なり、中央値パス（太線）だけが大きく離れる。**
- 「平均は同じ。真ん中の人生だけが違う」というキャプションを重ねる。
- 「もう一度」ボタンで乱数を振り直しても結論が変わらないことを見せる（＝偶然ではない）。

### S2. 分位ファン
5/25/50/75/95 パーセンタイルの帯（ファンチャート）を ρ=0 と ρ=0.7 で重ね描き。
上側は伸びるのに**中央値と下側が大きく沈む**。「上振れは増えたが、典型的な結果は悪化した」。

### S3. 「何年で2倍になるか」への翻訳（★初心者への最終翻訳）
成長率をパーセントで見せず、**倍化年数 `ln2 / g`** で見せる。

| ρ | 実質成長率 g | 資産が2倍になるまで |
|---|---|---|
| 0.0 | 7.6% | **9.2年** |
| 0.5 | 5.5% | **12.5年** |
| 0.8 | 4.3% | **16.1年** |
| （建玉2倍・ρ=0.8） | −0.6% | **永遠に来ない** |

**「相関を無視したら、2倍になるまでが9年から16年に延びた」** — パーセントより年数のほうが刺さる。
どの画面でも成長率の隣に必ず倍化年数を併記することを推奨。

## 10. 実装案（/portfolio への組み込み）

### 10.1 新規ライブラリ `app/lib/growth-drag.ts`

すべて純関数・O(N²) 以下。Worker 不要（スライダー即応が要件のため、むしろメインスレッド `useMemo` が正解）。

```ts
// ── 基本量 ──
export function geometricGrowth(mu: number, sigma: number): number;      // μ − σ²/2
export function effectiveN(N: number, rho: number): number;              // N/(1+(N−1)ρ)
export function effectiveNFromWeights(w: number[], R: number[][]): number; // (Σw)²/(wᵀRw) 実データ版
export function hiddenLeverage(N: number, nEff: number): number;         // √(N/N_eff)
export function doublingYears(g: number): number;                        // ln2/g（g≤0 は Infinity）

// ── 3項分解（G2 ウォーターフォール） ──
export interface DragDecomp {
  expected: number;      // W·μ
  soloDrag: number;      // W²σ²/(2N)   避けられない分
  corrDrag: number;      // W²σ²(1−1/N)ρ/2  相関の代償
  growth: number;        // g
  nEff: number; hiddenLev: number; doublingYears: number;
}
export function decomposeDrag(
  mu: number[], cov: number[][], w: number[]
): DragDecomp;          // 実データ版: soloDrag = Σw_i²σ_i²/2, corrDrag = σ_p²/2 − soloDrag

// ── 崖（G1） ──
export function growthCurve(
  mu: number, sigmaSingle: number, N: number, rho: number, wGrid: number[]
): { w: number; g: number }[];
export function peakExposure(mu: number, sigmaEff: number): number;      // μ/σ_eff²

// ── 台帳（T1） ──
export interface LedgerRow {
  ticker: string; corrToPrev: number; expected: number; sigmaP: number;
  drag: number; growth: number; nEff: number; hiddenLev: number; isPeak: boolean;
}
export function incrementalLedger(
  aligned: AlignedReturns, order: string[], mode: "split" | "add"
): LedgerRow[];          // mode="add" が「増し玉＝隠れレバ」、"split" が本物の分散

// ── シミュレーション（U1 / S1 / S2） ──
export function synthPaths(
  opts: { N: number; rho: number; mu: number; sigma: number; T: number; paths: number; seed: number }
): { perAsset: number[][]; portfolio: number[][] };   // 共通ファクター f + 個別 e で生成
export function quantileFan(paths: number[][], qs: number[]): number[][];
```

- 共通ファクター生成: `r_i,t = μ/T + σ_T·(√ρ·f_t + √(1−ρ)·e_i,t)`。**seed を固定**しておくことで、ρスライダーを動かしても「同じ乱数の世界で相関だけが変わった」ことが視覚的に保証される（U1 の要）。乱数は既存の `mulberry32` パターンを踏襲。
- `AlignedReturns` / `correlationMatrix` は既存 `app/lib/portfolio-risk.ts` から import して再利用（新規に整列ロジックを書かない）。
- `lambdaOf` / `growthRatio` は既存 `app/lib/weekly-allocation.ts` から import。**同じ概念を二重定義しない。**

### 10.3 チャート描画方式（CLAUDE.md の規約に対する判断）

規約は「横軸が時間の系列は原則 lightweight-charts」。本提案では以下のように切り分ける。**逸脱する箇所は理由を明示する。**

| 図 | 方式 | 理由 |
|---|---|---|
| G1 三本の崖 / G2 ウォーターフォール / G4 ヒストグラム / G5 円グラフ / U5 ゲージ / U4 卵 | **Canvas2D** | 横軸が時間でない静的図。規約どおり。 |
| U1 同期アニメ / S1 レース / S2 ファン | **Canvas2D（規約からの意図的逸脱）** | 横軸は時間だが、**合成データであり日付に意味がない**。価値は「スライダーに対する形の応答」であって期間の細部拡大ではなく、毎フレーム再描画するアニメーションに lightweight-charts は不向き。60fps 描画のため Canvas2D を採用する。 |
| T1 台帳から遷移する「実データの累積曲線」 | **lightweight-charts** | 実際の日付を持つ系列。期間の細部確認に価値があるため規約どおり。 |

### 10.4 AnalysisGuide（規約必須）

各コンポーネントに以下の7項目構成で付ける（CLAUDE.md 準拠）。本文素材は本ドキュメントの §5〜§7 をそのまま流用可能。

1. 手法の概要 — 算術平均と幾何平均のずれ、なぜ長期投資では後者だけが意味を持つか
2. 数式 — §7 全文（`g ≈ μ−σ²/2` の導出、N_eff、3項分解、λ）
3. 用語の定義 — ボラティリティ・ドラッグ／幾何平均／実効銘柄数／隠れレバレッジ／エルゴード性
4. 直感的な例え — §5 の比喩表（卵とカゴとトラック、占い師、和音、穴の空いたバケツ）
5. 結果の読み方 — 「N/N_eff = 5.5 なら、払っている税は本物の分散の5.5倍」「λ>2 の領域なら建玉を減らすことが唯一の改善策」
6. 投資判断への活用 — 買い増し前に N_eff の変化を見る／同業種の追加は分散でなく増し玉と認識する／建玉上限を λ<1 から逆算する
7. 注意点・限界 — μ の推定誤差は σ の推定誤差よりはるかに大きい（ケリー最適点は信用できない、**λ<1 側に倒す**）／相関は非定常でテール時に上がる（既存 `computeStress` の危機Σを参照）／`g ≈ μ−σ²/2` は2次近似で、テールが厚いと過小評価になる／過去相関が将来相関を保証しない

### 10.5 フェーズ分け

- **Phase 1（最小で最大の効果）**: `growth-drag.ts` ＋ `YourPortfolioDragPanel`（G2 ＋ U5 ＋ T1 ＋ S3）。既存の `alignReturns` / PCTR を流用するだけで、実データに対する「相関が食べた分」が即出る。
- **Phase 2**: `CorrelationDragChart`（G1 ＋ U1 ＋ ρスライダー）。合成データなので実装が独立していて壊れにくい。
- **Phase 3**: `GrowthIntuitionPanel`（U2 ＋ U3 ＋ T2）と `pf-frontier` への G6 等高線追加。
- **Phase 4（任意）**: 危機Σ連動 — ρスライダーの初期値に既存 `computeStress` の `rhoStress`（危機時の実測平均相関）を入れ、**「平時のあなた」と「暴落時のあなた」を2つのドットで崖の上に並べる**。暴落時ドットだけが崖の外に落ちているのが見える。

### 10.6 計算量と配置

- 全て O(N²)（N ≤ 30 のウォッチリスト規模）。既存 `PortfolioRiskPanel` と同じくメインスレッド `useMemo` で十分。Worker 不要。
- S1/S2 のモンテカルロだけ paths×T = 300×252 ≈ 7.5万点。生成は 10ms 未満だが、**ρスライダーのドラッグ中に毎回再生成すると重い**ので `requestAnimationFrame` でのスロットリング、または「ρ変更時はパスを再利用して相関ミックスのみ再計算」（同一 f と e を保持しておけば混合係数を変えるだけで済む）とする。後者が正しい実装で、かつ「同じ乱数の世界」の保証にもなる。
- 折りたたみは既存 `CollapsibleAnalysis` を使用し、ID を上記のとおり付けて localStorage 永続化に乗せる。
