0結論（先に）

  1. いちばん欠けているのは分析ではなく「台帳」である。 実際の建玉・現金・取引・損益・口座区分（NISA／特定／信用）をサーバーに持つ場所が無い。ウォッチリストの建玉欄は localStorage の含み損益%止まりで、損益の時系列も取引の理由も残らない。株式原論の命題3（翻訳されない確信は存在しないのと等価）を、このサイト自身が満たしていない。
  2. 資産形成に効くと実測で確かめられたのは5つだけ。 ①市場に参加し続ける床 ②セクターに集中しセクター内では b/σε で分散 ③複数ストレス指標＋ヒステリシスの現金退避（最大DD −83%→−34%、ただし保険） ④税と回転コストの控除（NISA分岐 R×1.255） ⑤執行時刻の最適化。この5つを1枚の「運用方針」に束ね、台帳で守られているかを毎月測るのが長期レーンの本体。
  3. 短期の方向予測は、この repo の検定を通らない。 SPA p=0.334、ヌル較正 +279%、as-of で方向・確率が全滅、ML でも長期OOSで IC≈0。残るのは「状態（荒れているか）」と「寄り付きの窓の約3割」で、後者は寄った瞬間に終わっている。短期レーンは「方向を当てる」から「状態でサイズを決め、執行で漏れを減らし、小さな研究スリーブで前向きに採点する」へ設計を変える。
  4. 価格だけでは測れない軸を足す。 決算日・権利落ち・信用残・空売り比率・国内金利（JGB）・時点構成銘柄が一つも無い。J-Quants を1本つなぐと5つ同時に埋まる。これは「銘柄選択」と「イベント回避」の両方の前提になる。
  5. 答えを出す画面が8か所に散っていて、互いに整合していない。 q提案（/axioms）・判定バッジ（/portfolio、等重み暫定）・今日のビン・期待パス・週次アナログ・クロスアセット窓・総合スコア・レジーム。出力を「q提案」1本に収束させ、他は入力に降格する。毎朝7時の1枚（寄り前ブリーフ）がその配信面になる。

結論の多くは 7203.T とメガバンク3行での実測に基づく。他の銘柄族では符号が変わりうる。本書は「何を作るか」の順序を決める文書で、各項目の数値は着手時に再測定する。

2設計原則 ─ 5つのレバーと、測れるかどうか

株式原論の会計恒等式がそのまま設計の物差しになる。

W(T) = Σi ∫ qi(t) dPi(t) − C　　E[W] = ∫E[q]E[dP]（参加項） + ∫Cov(q,dP)（エッジ項） − E[C]（摩擦項）

投資家が動かせるのは q の5成分だけで、この repo の実測は「どの成分が測れるか」を既に答えている。改善計画はその答えに従って配分する。

対象（どの資産）市場の床＋セクター集中＋b/σε。測れる。
→ 長期レーンの中心
大きさ |q|σ と状態は測れる。μ は測れない。
→ 状態でサイズ、μ は前提
符号・タイミングSPA・ヌル較正・as-of で裏付けなし。
→ 投資しない。研究スリーブのみ
保有期間回転が減るほど税とコストが減る。
→ 持ち切りが既定、例外を台帳で管理
摩擦 C符号確定・測定可能。実コストは楽天表で既に一元化。
→ 執行と税で確実に拾う

結果として、長期レーンが主、短期レーンは従になる。これは好みではなく、この repo の検定結果からの帰結である。短期レーンに残す仕事は「状態によるサイズ調整」「執行品質」「前向きに採点される小さな実験」の3つに限る。

3長期運用レーン ─ 測れる5つを1枚の方針に束ねる

L1

運用台帳（実建玉・現金・取引・損益・口座区分）をサーバーに持つ

最優先他の全項目の前提
何を
口座（NISA成長／つみたて／特定／信用）× 銘柄 × 取引（日付・売買・株数・単価・手数料・税区分）× 理由（どのパネルの、q のどの成分を根拠にしたか）を記録する。派生して、評価額・現金比率・実現／未実現損益・税見込み・回転率・コスト実額・ファクター露出（市場β、セクター b）を日次で出す。
なぜ
命題3。確信は建玉に翻訳されて初めて損益になる。今は翻訳の記録が無く、「分析が資産形成に効いたか」を原理的に測れない。毎月の W を 参加項／エッジ項／摩擦項／税 に分解できる唯一の場所になる。
足場
app/lib/ledger-db.ts（Postgres、owner_id、UNIQUE制約の作法）、ledger-owner.ts（匿名オーナーcookie）、nisa-vs-taxable.ts の清算価値ウォーカー（税計算を流用）、rakuten-margin.ts（信用コスト）、watchlist.ts の position 型（移行元）。
受け入れ
①任意の月について「W = Σq·ΔP − C」の分解表が台帳だけから再現できる ②税見込みが nisa-vs-taxable と同じ数値になる ③端末を変えても建玉が消えない ④503 時は localStorage 退避と画面開示（LedgerSyncBar と同じ）
注意
認証が無いので匿名オーナーモデルの限界（cookie 消失＝喪失）を画面に書く。復元キーの発行を最初から入れる。
L2

投資方針書（IPS）ページ ─ 測定値から生成し、乖離を台帳で監視する

長期の中核
何を
①参加：市場の床に常時参加する比率の下限 ②対象：セクター集中の有無、k=5〜8本、w∝b/σε²、純度目標とヘッジ比率 h ③大きさ：μ=6% 前提の fractional Kelly 上限、DD 許容 ④保有：持ち切り既定、回転の上限（回／年） ⑤税：NISA に入れる銘柄の規則 ⑥デリスク：L3 の規則とパラメータ ⑦リバランス：ウェイトの乖離帯と見直し周期。これらを版管理された文書として保存し、台帳（L1）の現状との乖離を数値で表示する。

5つの発見が別々のパネルに散っていて、運用規則として1か所に書かれていない。方針が文書化されていないと、相場が荒れた日に「分析」が「願望」に戻る。

pf-sector-select（w の計算）、kelly-uncertainty.ts、growth-drag.ts（g の3項分解）、mu-mode-store.ts（μ 前提の共有）、corollaries.ts（各規則の公理的根拠へのリンク）。

L5

NISA 枠配分と口座跨ぎの最適化

何を
台帳の建玉候補を「NISA（非課税・持ち切り向き）／特定（回転・ヘッジ向き）／信用（ショート・レバ）」に振り分ける規則を計算する。目安は g が高く回転が低いものを NISA へ、ヘッジと短期スリーブは課税口座へ。年初一括と分割の比較、枠の繰越可否、損益通算の非対称（NISA は損失を通算できない）を数値で見せる。
なぜ
税項は g に比例する（sim-holding-ledger）。同じ銘柄・同じ q でも口座を変えるだけで最終資産が変わる唯一のレバーで、しかも符号が確定している。
足場
nisa-vs-taxable.ts（GROWTH_QUOTA / ANNUAL_QUOTA、Model A/B）、pf-entry-sizing（待つ価値は t=0.95 で裏付けなし → 年初一括を既定にしてよい根拠）。

検証基盤
何を

デリスク研究で「2020年以降だけ見ると α+13%（t=2.3）、2012年以降に延ばすと消える」が実証された。10年窓は短期の偽陽性を見抜けない。先行指標研究も 2008〜09 年限定の現象を10年窓では区別できなかった。

4短期トレードレーン ─ 方向を当てる設計をやめる

この repo の短期分析は calendar 節だけで56本あり、そのほとんどが「いつ建てるか」を探している。検定の結果は一貫して「裏付けなし」である。短期レーンに残す価値があるのは、符号ではなく次の3つの仕事であり、設計をそこへ寄せる。

S1

短期パネル共通の「採否バッジ」（門番）

横断部品
何を
戦略の形をしたパネル全てに、同じ4点を自動で付ける。①実コスト控除後の年率（楽天実コスト既定） ②スヌーピング補正 p（SPA／BH-FDR） ③as-of スコアカードでヌルを超えているか ④容量 K* と自分の建玉額の比。4点から「使える／保留／使えない」を1つのバッジにし、「使えない」は既定で折りたたむ。
なぜ
cal-timing-value の SPA と edge-capacity の K* は既にあるが、各パネルに個別に貼られていない。利用者は56本を1本ずつ読んで、どれが本物かを自分で判断させられている。情報源としての価値は「どれを読まなくてよいか」を言えることにある。
足場
StrategyVsBenchmark（コスト後、8箇所配線済）、timing-value.ts、edge-capacity.ts、asof-replay.ts、panel-registry.tsx（1レコードに gate 関数を持たせる）。
受け入れ
7203.T で calendar 節の56本のうち「使える」が何本残るかを数字で報告できる。合成データで植え込みエッジ（週末 −0.3%）が「使える」に、エッジゼロが「使えない」になる。
S2

寄り前ブリーフ（毎営業日 7:00 JST の1枚）

配信面cron 必要
何を
1ページに ①デリスク4灯の状態と閾値までの距離（L3） ②次の寄り付きの窓の目安 ±1σ（既存 causal-cross-asset） ③今日のイベント（FOMC／日銀／SQ／保有銘柄の決算・権利落ち：D1） ④保有建玉のストップ／目標との距離、方針（L2）からの乖離 ⑤q提案（E1）の変更有無。既定の出力は「今日は q を変えない」で、変える日だけ理由と執行時刻（S3）を添える。Vercel Cron で生成し、メールまたは push で届ける。
なぜ
8つの判定画面を毎朝開いて回る運用は続かない。年3回の点灯を拾うには配信が要る。窓の目安は「寄りで建てる人には取れない」が、「今日 q を変える予定の人が寄りと引けのどちらで執行するか」には使える。
足場
cross-asset-lead.ts、event-calendar.ts、q-synthesis.ts、台帳（L1）。配信は Vercel Cron（vercel.ts の crons）＋ メール送信サービスを1つ選ぶ。
受け入れ
米国終値が未確定の日は「6〜7時に更新」と出る（既存の挙動を踏襲）。ブリーフの各行が、それを出したパネルへのリンクを持つ。配信された判断は判断ログ（V1）に自動で残る。
S3

執行品質 ─ 予定した q 変更をいつ・どう約定させるか

符号確定の価値
何を
台帳に「予定した q 変更」を登録すると、cal-exec-timing／cal-sliced-exec（TWAP/VWAP）／cal-highlow-timing から執行計画を出し、約定後に VWAP・終値・寄り値に対する実装ショートフォールを記録する。月次で「執行で失った bp」を摩擦項として台帳に積む。
なぜ
命題5。短期の技術のうち、価値の符号が確定しているのは執行だけ。cross-sectional の実証で「終値で建てられず bid-ask を跨ぐ」だけで −63% が消えた。短期分析の投資先として最も確実。
足場
日中足は /api/intraday（60分足 730日）。スプレッド推定は sa-risk-spread（Corwin-Schultz）。
S4

イベント駆動の事前登録スタディ（決算・権利落ち・日銀・SQ）

D1 に依存
何を
銘柄固有イベント（決算発表日・権利落ち日）と市場イベントの前後 K 日の分布を、cal-event-effect の枠で出す。仮説は事前登録（edge-ledger の凍結）し、OOS で採点する。短期で「避けるべき日」「持ち越さない日」を規則にする。
なぜ
日足の方向はヌルでも、イベント日の分散は確実に大きい（状態は当たる）。「何もしない日」を決める材料としては価値がある。現状の FOMC/CPI/日銀は静的表で、銘柄固有イベントが無い。
S5

短期の研究スリーブ ─ 上限を固定し、全件を前向きに採点する

何を
台帳に「研究スリーブ」口座区分を作り、資本の一定割合（例 5%）を上限にする。この区分の売買は必ず仮説（パネルID・エッジID）を伴い、edge-decay の SPRT＋CUSUM で死亡判定、asof-scorecard で方向・確率・区間を採点する。四半期ごとに「生きている仮説」だけが上限を使える。
なぜ
短期トレードをやめろと言う設計は実行されない（親御さんの例のとおり）。代わりに「小さく、記録し、殺す基準を先に決める」形にすると、損失は上限で止まり、当たった仮説は証拠つきで本体に昇格できる。Simons／Thorp 系譜の規律そのもの。
足場
edge-decay.ts、prospective-ledger.ts、asof-replay.ts、台帳（L1）。

6検証と規律 ─ 「分析→建玉」の輪を閉じる

V1

判断ログと「自分の判断」の as-of 採点

何を
台帳（L1）の全取引と、ブリーフ（S2）で出た「変えない」判断を、判断の型（方向・確率・区間・ボラ・警告）で分類して保存する。3か月後から asof-scorecard と同じ採点則（PT／Brier／Christoffersen／MZ／Welch）で、モデルではなく自分の判断を採点する。
なぜ
as-of 検証は先読みを消せるが探索バイアスは消せない。前向きの記録だけが本物の検証で、着手が1日遅れるごとに記録が1日減る性質を持つ（asset-utilization §2-6）。
V2

答えの出口を q提案1本に収束させる

何を
TodayQProposal を唯一の「どうするか」の出力と定め、判定バッジ・今日のビン・期待パス・週次アナログ・レジーム・総合スコアはその入力（寄与）に降格する。各寄与には as-of スコアカードの成績が重みとして付き、ヌルを超えない寄与（7203.T の方向・確率）は自動で 0 になる。戦略ラボの閾値は「凍結→OOS で生存→ライブ採用」の道筋を通さないと反映されない。
なぜ
8つの出口が別々に光ると、利用者は自分に都合のよい方を選ぶ（＝スヌーピングを UI がやらせている）。
V3

月次レビューページ

何を
台帳から ①W の分解（参加／エッジ／摩擦／税） ②DD と方針の許容 ③回転率 ④執行ショートフォール ⑤方針からの乖離 ⑥研究スリーブの生死 を1枚に出す。月初に自動生成して配信する。
V4

公開トラックレコード（1年後）

何を
既定の計画どおり、台帳の凍結記録が1年分たまってから /track-record を公開する。失敗も含めて全件が自動採点で並ぶ。薄い実績を早く出すのは、このサイトが最も批判している行為なので待つ。
