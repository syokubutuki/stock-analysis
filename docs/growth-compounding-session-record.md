## 2. 設計の根拠 ─ 実測が当初の仮説を棄却した

**着手時の仮説は「高ボラ銘柄の短期売買は幾何リターンを壊す」だった。実測で棄却された。**

285A.T（キオクシア, 2024-12上場, 1.6年）を `/api/stock` 経由で取得して測ると:

```
μ_arith = 264.3%   σ = 102.8%   壁 σ²/2 = 52.8%   g実現 = 208.4%
1,601円 → 52,500円（32.8倍）  dataQuality.repaired / suspects ともに空（破損なし）
```

**μ が壁を遥かに越えている。ボラティリティドラッグは巨大だが銘柄の成否を決めていない。**
ドラッグを主役に据えた画面を作ると、実データを入れた瞬間に自己矛盾する。

代わりに成立したのは2つだけで、実装はこの2つに沿っている。

1. **SE(μ̂)=σ/√T が壁より大きい**（285A: ±80.4pp > 52.8pp ／ 8306の10年: ±9.1pp > 4.0pp）。
   壁を越えているかは測定では決着しない。差は「必要な信念の大きさ」。
2. **回転コストと税は符号が確定していて測れる。** 税項は g に比例するので、
   **当たっている銘柄ほど回転の損失が大きい**。

利用者はこれを踏まえ「**両方を並べて見せる**（ドラッグでは説明できなかったこと自体を教材にする）」
を選択した。`sim-holding-ledger` の「どちらが削ったか」2本バーはその要求に対応する。

### 再現方法

> **2026-09-02 訂正。** 「恒等式の残差が全銘柄で1pp以内」は 285A.T で **−1.03pp** 出る。
> 10年ある銘柄（8306 / 6501 / 7203）は 0.03pp 以内。高ボラ・短標本では 1pp を超えうるので、
> 回帰テストの閾値は 2pp に置いてある。

いずれも `/api/stock?ticker=…&range=10y` から取得し（**Yahoo を直接叩かない**の規約どおり）、
`holding-ledger.ts` の `seriesStats()` に通せば同じ数字が出る。計測用スクリプトはリポジトリ外
（セッションの一時領域）に置いたので残っていない。再測が要るなら `seriesStats` を呼ぶ
10行程度で足りる。

## 5. ★ レビューで特に見てほしい箇所（自分で怪しいと思っている所）

### ① `open-close-edge.ts` ─ 検定をネットに切り替えた判断

コスト有効時に **t・p・FDR・CI・Sharpe・最大DD・年次符号のすべてをネットで再計算**している。
「グロスで検定し、ネットは経済的評価として併記する」設計もありえた。
私は「取り出せるエッジがあるか」を検定したかったので前者にしたが、
**FDR の母数と選抜がコスト設定に依存する**ことになる。ここは思想の問題なので見てほしい。

### ② `deduct` の既定を true にしたこと

§0② のとおり既存パネルと方針が逆。この表は cadence 1〜21日を同じ順位表に並べるので
グロス既定だと比較が成立しない、というのが理由。**既定を変えずに警告だけ出す**選択もあった。

### ③ `holding-ledger.ts` の税モデル

`afterTaxAnnualLog` は「H日ごとに実現・損益通算あり・決定論的な正ドリフト」の近似である。
経路依存な厳密計算は `nisa-vs-taxable.ts` にあるのに接続していない。

> **2026-09-02 訂正。** ここに書いていた「実測ではこの近似が**保守側**に出る
> （台帳の予測がプラセボ分布の中央より左に来る）」は**原因の診断が誤り**だった。
> 税の近似ではなく `placeboDistribution` の往復回数不足（下の ⑪）が原因である。
> コストと税をゼロにすると台帳とプラセボ中央値は 0.25pp 以内で一致し、
> **分解そのものは妥当**だった。近似の妥当性は依然として未検証。

### ④ `walkStrategy` のコスト適用箇所

建玉時と手仕舞い時に片道 `q·c/2` ずつ（合計 `q·c`）。レバレッジ時に自己資本比で
`q·c` を引くのが正しいかは判断が要る。

### ⑤ `muSigmaPersistence` の2分割固定

分割点の選び方に結果が依存する。結論（μ の順位相関が σ より大幅に低い）は頑健だと
思っているが、**個々の数値は点推定**である。K分割やローリング窓は実装していない。

### ⑥ 順位相関そのものの標本誤差

12銘柄で Spearman(σ)=0.42、Spearman(μ)=0.00。**N=12 の順位相関はそれ自体の
標準誤差が大きく（およそ 1/√(N−1)≈0.30）、この2つの差は有意ではない可能性がある。**
ガイドの注意点には書いたが、本文の言い切り方が強すぎないか見てほしい。
利用者のウォッチリスト銘柄数によっては、さらに弱い標本で断定的な文言が出る。

### ⑦ 恣意的な閾値が3つある

| 定数 | 場所 | 根拠 |
|---|---|---|
| `MIN_YEARS_FOR_T = 3` | `kelly-uncertainty.ts` | 「1つの相場つきしか見ていない」の目安。根拠は弱い |
| `MIN_BLOCKS = 20` | 同・`frequencyLadder` | 285A.T の63日集計が n=6 で暴れたので置いた |
| `minHalfDays = 252` | `mu-sigma-persistence.ts` | 片方の半分に必要な最低営業日数 |

### ⑧ `KellyChart` の既定 belief = 6%

「実測μを既定にすると、また点推定を答えとして提示することになる」という理由で
株式のリスクプレミアム相当を既定にした。**日本株で6%が妥当か**は議論の余地がある。

### ⑨ `seriesStats()` を2パネルで共有していること

`sim-kelly` と `sim-holding-ledger` が同じ関数から μ・σ・壁を取る（数値の食い違いを
防ぐため意図的）。**片方の都合で `seriesStats` を変えると他方が黙って動く**。

### ⑩ 他パネルに同じ問題が残っている

`kelly-bs.ts` の `kellyOptimal()` は触っていない（他に3箇所が使用中のため）。
そのうち **`ConsolidatedScorecardChart` は `f* > 0.3` を「強気」判定に使っている**ので、
`sim-kelly` で問題にした点推定依存がそのまま残っている。
`axioms/q-synthesis.ts` は `min(halfKelly, varCap)` なので VaR 上限が実質的に守っている。

> **2026-09-02 訂正。** 「他に3箇所が使用中」は誤りで、**2箇所**である
> （`ConsolidatedScorecardChart.tsx:62` と `axioms/q-synthesis.ts:246`）。
> また問題は点推定依存より重かった。`f* > 0.3 ⟺ μ > 0.3σ²` なので σ=30% なら
> 年2.7%で成立し、**上昇局面ではほぼ常に「強気」を返していた**
> （実測5銘柄すべて強気: 8306=333% / 6501=278% / 7203=223% / 285A=251% / 投信=563%）。
> 閾値を `f* > 1`（現物フル超）に変更済み。

前者は `1/√(N−1)` を閾値にして8銘柄以下では結論を出さないようにし、後者は
頻度ラダーに**分散比の列**を足した（6501.T の 63日集計は分散比 0.56 で、
